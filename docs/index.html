기초

Python·문제 정의·데이터 품질·통계·변수 진단

0. Python과 데이터 분석 기초신용모형 개발에 필요한 최소한의 Python·pandas 도구를 익히고, 작은 대출 데이터를 읽어 품질 점검까지 할 수 있게 된다.1. 신용평가 문제 정의와 모집단 선정모형 개발의 첫 단계는 알고리즘이 아니라 "무엇을, 누구에 대해, 언제부터 언제까지 예측하는가"를 문서로 고정하는 일이다.2. 데이터 품질과 탐색적 분석모형은 데이터가 말하는 만큼만 안다. 결측·중복·이상치·타깃 누수를 먼저 찾고, 분포와 부도율을 눈으로 확인한 뒤에야 변수를 만진다.3. 통계와 확률 기초부도율, 신뢰구간, p-value 같은 말을 *정확한 뜻*으로 쓰기 위한 최소한의 확률·통계 도구.4. 단변량·다변량 분석과 변수 진단변수를 *하나씩* 보고, 다음엔 *함께* 보고, 마지막에 "이 변수를 모형에 넣어도 되는가"를 여러 근거로 결정한다. p-value 하나로 결정하지 않는다.

로지스틱 CSS

비닝/WOE/IV → 로지스틱 회귀 → 스코어카드

5. 비닝·WOE·IV연속형 변수를 구간으로 나누고, 구간마다 "얼마나 위험한가"를 로그 비율(WOE)로 바꾼 뒤, 변수 전체의 정보량(IV)을 요약한다. 스코어카드의 재료가 되는 과정이다.6. 로지스틱 회귀의 수학과 해석확률을 직접 직선으로 맞추지 않고 *로그오즈*를 직선으로 맞춘다. 계수 하나가 "오즈를 몇 배로 바꾸는가"로 읽힌다는 점이 신용모형의 해석력의 근간이다.7. 규제형 로지스틱 CSS와 스코어카드로지스틱 모형이 만든 로그오즈를 "점수"로 바꾸고, 점수를 "등급"으로 묶고, 등급별 부도율을 검토한다. 모형(예측)과 정책(컷오프)은 분리한다.

검증과 모니터링

분할·누수 방지 → 평가지표 → PSI·드리프트

8. Train/Validation/Test, 교차검증과 누수 방지모형의 성적은 "처음 보는 데이터"에서만 의미가 있다. 데이터를 어떻게 나누고, 전처리를 어디에서 하며, 테스트를 몇 번 보느냐가 결과의 신뢰성을 정한다.9. 평가 지표와 검증모형이 "좋다"는 말은 지표마다 다른 뜻이다. 순위를 잘 맞히는가(변별력), 확률 값이 맞는가(보정), 특정 컷오프에서 어떤 오류가 나는가(분류 성능)를 *따로* 본다.10. PSI·안정성·드리프트모형은 "개발 때 본 세상"에서 만들어졌다. 세상이 변하면 입력 분포도, 변수와 부도의 관계도 변한다. PSI 는 *분포가 얼마나 달라졌는가*를 재는 첫 번째 경보기일 뿐, 모형이 틀렸다는 증명이 아니다.

머신러닝

트리 부스팅 → 튜닝·보정 → 합성 데이터(GAN)

11. 트리·부스팅·SHAP트리는 "조건 분기"로 데이터를 쪼개고, 부스팅은 그런 작은 트리를 *앞선 모형의 실수를 고치는 방향*으로 계속 더한다. 성능은 올라가지만 설명 가능성과 안정성의 비용을 치른다.12. 튜닝·앙상블·보정튜닝은 "검증 데이터에 맞춰 설정을 고르는 일"이므로, 그 데이터는 이미 *오염*되었다. 최종 성능은 **한 번도 쓰지 않은** 데이터로만 말한다. 그리고 순위가 좋은 모형도 확률이 틀리면 PD 가 아니다.13. GAN과 합성데이터합성데이터는 "진짜 데이터의 대용품"이 아니라 "진짜 데이터의 *통계적 그림자*"다. 그림자가 얼마나 닮았는지(충실도), 그림자로 학습해도 현실에서 통하는지(유용성), 원본 개인을 드러내지 않는지(프라이버시)를 *각각* 확인해야 한다.

통계 심화·운영·캡스톤

검정의 올바른 사용 → 운영·위험관리 → 종합 프로젝트

14. 가설검정·p-value·DeLong·다중검정"AUROC 가 0.003 올랐다"는 것만으로는 개선이 아니다. 그 차이가 *표본이 달라져도 반복될 변동*보다 큰지를 따져야 한다. 검정은 그 질문에 답하는 도구이고, p-value 는 흔히 오해된다.15. 고급 주제와 운영: 거절 추론·충당금·설명·공정성·모형위험관리모형은 개발이 끝나면 시작이다. 운영 환경에서는 "누구의 데이터로 배웠는가(선택 편향)", "확률이 돈이 되는 방식(충당금)", "고객에게 어떻게 설명하는가", "누가 불리해지는가", "누가 책임지는가"가 문제가 된다.16. 종합 프로젝트: 처음부터 끝까지앞 단계의 모든 선택(목표 정의, 정제, 분할, 비닝, 모형, 평가, 보정, 모니터링, 문서화)을 *하나의 재현 가능한 흐름*으로 묶는다. 합격 기준은 높은 AUROC 가 아니라 **각 결정을 근거와 함께 설명할 수 있는가**이다.
