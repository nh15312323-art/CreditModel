4. 어떻게 작동하는가

4-1. 값과 자료형

변수는 값에 붙인 이름이다. 값에는 종류(자료형)가 있고, 종류에 따라 가능한 연산이 다르다.

n_total = 10_000          # int(정수)
n_default = 450
rate = n_default / n_total  # float(실수)  → 0.045
name = "개인신용"           # str(문자열)
is_default = rate > 0.04    # bool(참/거짓)
print(rate, type(rate).__name__, is_default)
assert abs(rate - 0.045) < 1e-12

직관: / 는 항상 실수를 돌려주고 // 는 몫, % 는 나머지다. 부도율처럼 비율을 구할 때는 분모가 0이 아닌지 먼저 확인한다(0으로 나누면 ZeroDivisionError).

4-2. 조건문·반복문·함수·예외 처리

def default_rate(n_default, n_total):
    """부도율 = 부도 건수 / 전체 건수. 분모가 0 이하면 계산하지 않고 멈춘다."""
    if n_total <= 0:
        raise ValueError("전체 건수는 1 이상이어야 합니다.")
    return n_default / n_total

for d, n in [(45, 1000), (3, 50), (0, 200)]:
    print(d, n, f"{default_rate(d, n):.1%}")

try:
    default_rate(1, 0)
except ValueError as e:
    print("오류를 잡았습니다:", e)

함수는 입력 → 출력 이 분명해야 한다. 이 프로그램의 creditlab 함수들은 모두 이 원칙으로 만들어져 있다. 예외는 숨기지 말고, 무엇이 문제인지 알려 주며 멈추는 것이 안전하다.

자료형 모양 특징 신용모형 예

4-4. NumPy: 숫자 배열

import numpy as np

p = np.array([0.01, 0.05, 0.10, 0.50])
odds = p / (1 - p)           # 원소별 계산 (반복문 없이)
logit = np.log(odds)
print(np.round(odds, 4), np.round(logit, 4))
assert np.allclose(logit[1], np.log(0.05 / 0.95))

한 번에 배열 전체를 계산하는 것을 벡터화라 한다. 반복문보다 짧고 빠르다. 로지스틱 회귀의 odds, logit 계산이 바로 이 형태다(단계 6).

4-5. pandas: 표 데이터

import pandas as pd

df = pd.DataFrame({
    "id": [1, 2, 3, 4, 5, 6],
    "age": [25, 40, 33, 58, None, 47],
    "region": ["A", "B", "A", "C", "B", "A"],
    "default": [0, 1, 0, 0, 1, 0],
})
print(df.shape)                      # (행, 열)
print(df["age"].isna().sum())        # 결측 건수
print(df.loc[df["age"] > 30, "id"].tolist())    # 조건 필터 (결측은 False 로 취급됨)
by_region = df.groupby("region")["default"].agg(n="size", rate="mean")
print(by_region)
assert by_region.loc["A", "n"] == 3 and abs(by_region.loc["A", "rate"]) < 1e-12

핵심 동작 네 가지만 기억하자.

  • 선택: df["col"], df.loc[행조건, 열], df.iloc[위치]
  • 필터: df[df["age"] > 30] — 결측(NaN)은 비교가 항상 False가 되어 조용히 빠진다. 결측이 있는 열로 필터링할 때는 빠진 행이 얼마인지 확인한다.
  • 그룹화: groupby(...).agg(...) 으로 부도율·건수를 구한다(단계 5의 비닝 표가 이것이다).
  • 병합: pd.merge(left, right, on="id", how="left", validate="one_to_one"). validate 를 쓰면 중복 키로 행이 늘어나는 사고를 막는다.
accounts = pd.DataFrame({"id": [1, 2, 3], "limit": [500, 800, 300]})
customers = pd.DataFrame({"id": [1, 2, 2, 3], "age": [30, 40, 40, 50]})   # id=2 중복
try:
    pd.merge(accounts, customers, on="id", how="left", validate="one_to_one")
except pd.errors.MergeError as e:
    print("병합 검증이 중복 키를 잡았습니다")

  • 데이터는 행 = 관측, 열 = 변수 인 정돈된(tidy) 표라고 가정한다.
  • 같은 열의 값은 같은 의미·단위·자료형이어야 한다 (단위가 섞이면 코드가 정상이어도 결과는 틀린다).

6. 한계와 오용

자주 하는 실수

  • 원본을 덮어쓰기: df["age"] = ... 는 원본을 바꾼다. 정제는 df.copy() 로 복사본에서 한다.
  • 결측 필터의 함정: df[df["x"] != 3] 은 x 가 결측인 행을 포함하고, df[df["x"] == 3] 은 제외한다. 의도와 맞는지 건수를 확인한다.

  • 노트북 상태 의존: 실행 순서가 뒤섞이면 어제 결과가 오늘 재현되지 않는다. 마지막엔 런타임 재시작 후 모두 실행으로 확인한다.

  • 타깃 정의서를 작성하고, 데이터 분할 전에 모집단 정의를 고정해야 하는 이유를 말한다.

1. 왜 생겼는가

초기 대출 심사는 심사자의 경험에 의존했다. 같은 신청자도 사람마다 판단이 달랐고, 판단의 근거는 기록되지 않았다. 20세기 중반 이후 과거 대출의 결과(상환/연체)와 신청 시점 정보의 관계를 통계로 정리해 일관된 점수를 만들려는 시도가 상용화되었다.

그런데 통계모형은 "무엇을 맞힐지"가 정해져야만 만들 수 있다. 같은 연체 데이터라도 30일 연체를 부도로 보는지, 90일 연체를 부도로 보는지, 6개월을 보는지 12개월을 보는지에 따라 부도율도, 변수의 중요도도, 모형도 달라진다. 은행 규제(바젤)가 부도의 참조 정의와 PD 추정 관점(통상 1년 기간)을 정리한 이유가 여기에 있다.

2. 왜 필요한가

타깃 정의는 이후 모든 단계의 기준이다.

  • 정의가 흔들리면 개발 때와 운영 때 숫자가 맞지 않는다(예: 개발은 90일, 모니터링은 30일 기준).
  • 정의가 모호하면 검증자가 결과를 재현할 수 없다.
  • 모집단이 잘못되면 아무리 좋은 모형도 쓰일 곳과 다른 사람들에 대해 학습한 것이 된다.

3. 무엇을 하는가

타깃 정의서를 쓴다. 최소한 다음 7가지를 문장이 아니라 측정 가능한 규칙으로 적는다.

항목 질문 예 (가상 소액신용대출)
관측단위 행 1개는 무엇인가 대출 신청 1건 (고객 단위 중복 제거 후)
기준시점 설명변수는 어느 시점 정보인가 신청일 현재

부도 정의 무엇이 1인가 성과관찰창 내 원리금 90일 이상 연체

4. 어떻게 작동하는가

4-1. 부도 정의와 cure/재부도

부도 정의는 보통 연체 일수 기준과 상환 가능성 기준으로 구성된다. 바젤 규제의 참조 정의는 90일 초과 연체 또는 채무자가 채무를 이행하지 못할 가능성이 높다고 판단되는 경우(unlikely to pay)를 포함한다. 실제 국가·은행별 적용은 해당 시점의 감독규정과 내부 방법론을 확인해야 한다.

연체했다가 정상으로 돌아온(cure) 경우도 정의가 필요하다. 일정 기간(관찰 유예기간, probation) 정상이면 부도에서 벗어난 것으로 보고, 그 이후 다시 연체하면 재부도(re-default) 로 볼지 같은 규칙을 문서화한다. 이 규칙이 다르면 같은 포트폴리오의 부도율이 달라진다.

4-2. 개발모집단과 적용모집단: 선택 편향

대출 모형은 흔히 승인되어 대출이 실행된 사람의 성과만 관측된다.

구분 설명 문제
적용모집단(through-the-door) 모형을 실제로 쓸 신청자 전체 거절된 사람의 부도 여부는 모름
개발모집단 성과가 관측된 사람 과거 심사 정책이 걸러낸 사람들만 있음

과거 정책이 위험한 사람을 이미 많이 걸렀다면, 개발 데이터에는 그런 사람이 적다. 이 데이터로 만든 모형은 위험한 구간에서 정보가 부족하다. 이를 선택 편향(selection bias) 이라 한다. 거절 고객의 성과를 추정해 보완하려는 방법을 reject inference(augmentation, parceling, fuzzy augmentation 등)라 하지만, 관측되지 않은 결과를 가정으로 채우는 방법이라 효과는 가정에 크게 의존하고 학술적으로도 논쟁이 있다(Crook & Banasik, 2004). 따라서 한계를 문서화하고 민감도를 확인하는 것이 현실적인 접근이다.

4-3. 그 밖의 편향과 시점 문제

  • 생존 편향: 오래 유지된 계좌만 남은 데이터로 학습하면 이미 부도난 계좌가 사라진 표본이 된다.
  • 시점 불일치: 설명변수 일부가 기준시점 이후에 갱신된 값이면 미래 정보가 섞인다(단계 2의 누수).
  • 중복 고객/계좌: 한 고객이 여러 행이면 같은 사람이 학습·검증에 동시에 들어갈 수 있다(단계 8의 그룹 분할).
  • 표본추출: 부도가 드물면 부도 표본을 많이 뽑는 층화 추출을 쓸 수 있으나, 이때는 표본가중치로 실제 부도율을 복원해야 확률이 맞는다.

4-4. 표본 수와 이벤트 수

로지스틱 회귀의 추정 정밀도는 전체 건수가 아니라 적은 쪽 클래스의 건수에 크게 좌우된다. 10만 건 중 부도가 50건이면 정보량은 사실상 50건 수준이다. "변수 하나당 이벤트 10건" 같은 경험칙이 쓰이지만, 이는 통계적 법칙이 아니며 필요한 표본 크기는 목적·모형 복잡도에 따라 달라진다(van Smeden et al., 2019). 이 프로그램은 sample_sufficiency() 로 경고만 한다.

4-5. 제외 건수 추적

모집단을 줄여 갈 때는 어떤 규칙이 몇 건을 제외했는지를 순서대로 기록한다. 아래 표는 가상의 예다.

단계 규칙 제외 남은 건수
0 기간 내 신청 전체 - 10,000
1 중복 신청 제거 200 9,800
2 대상 아님(법인·미성년 등) 100 9,700
3 거절/미실행(성과 미관측) 2,200 7,500

최종 개발 대상 7,500건 중 부도가 300건이면 부도율은 300 ÷ 7,500 = 4.0% 다. 미실행 2,200건은 성과를 모르는 사람이므로 선택 편향의 원인이 된다는 점도 같이 기록한다.

import pandas as pd

def apply_exclusions(df, rules):
    """rules: [(규칙 이름, 제외 조건을 돌려주는 함수)]. 순서대로 적용하며 제외 건수를 기록한다."""
    log, current = [{"step": "시작", "excluded": 0, "remaining": len(df)}], df
    for name, cond in rules:
        mask = cond(current)
        log.append({"step": name, "excluded": int(mask.sum()), "remaining": int((~mask).sum())})
        current = current[~mask]
    return current, pd.DataFrame(log)

apps = pd.DataFrame({
    "id": [1, 2, 2, 3, 4, 5],
    "age": [30, 17, 17, 45, 52, 38],
    "approved": [1, 1, 1, 0, 1, 1],
})
kept, funnel = apply_exclusions(apps, [
    ("중복 ID", lambda d: d["id"].duplicated()),
    ("만 19세 미만", lambda d: d["age"] < 19),
    ("미승인(성과 미관측)", lambda d: d["approved"] == 0),
])
print(funnel)
assert funnel["remaining"].tolist() == [6, 5, 4, 3]
assert kept["id"].tolist() == [1, 4, 5]

5. 가정

  • 부도 정의와 성과관찰창은 개발·검증·운영에서 같다(또는 차이가 문서화되어 있다).
  • 개발모집단은 적용모집단을 충분히 대표한다. 대표하지 못하면 그 차이를 알고 있어야 한다.
  • 설명변수는 기준시점에 실제로 이용 가능하다(데이터 지연·소급 수정 포함).
  • 관측단위의 독립성: 같은 고객의 여러 행은 독립이 아니다.

6. 한계와 오용

자주 하는 오용

  • 데이터를 먼저 분할하고 나중에 제외 기준을 바꾸면, 검증 데이터의 정의가 학습 데이터와 달라진다. 모집단 정의를 먼저 고정한 뒤 분할한다.
  • 성과관찰창이 끝나지 않은 최근 신청 건을 "정상"으로 처리하면 부도율이 과소추정된다(아직 부도 날 시간이 없었을 뿐이다).
  • 부도율이 낮다고 해서 표본이 충분하다는 뜻이 아니다. 이벤트 수로 판단한다.
  • reject inference 결과를 "거절 고객의 진짜 성과"처럼 말하지 않는다. 그것은 가정의 산물이다.
  • 공개 데이터의 타깃 정의(예: UCI 의 1개월 후 결제 불이행)는 은행 IRB 의 12개월 부도 정의와 다르다.

단계 2. 데이터 품질과 탐색적 분석

모형은 데이터가 말하는 만큼만 안다. 결측·중복·이상치·타깃 누수를 먼저 찾고, 분포와 부도율을 눈으로 확인한 뒤에야 변수를 만진다.

연결 실습: 노트북 03_missing_and_quality · 코드 creditlab.data.validation, creditlab.reporting.quality_report

학습 목표

  • 데이터 사전을 만들고 단위·값 범위·자료형을 점검한다.
  • 결측의 세 가지 메커니즘(MCAR/MAR/MNAR)을 직관적으로 구분한다.
  • 이상치를 입력 오류와 실제 극단값으로 나누어 다룬다.
  • 타깃 누수 유형을 열거하고 의심 변수를 찾는 질문을 만든다.
  • 단변량 분석과 타깃별 비교를 수행하고, 하위집단의 데이터 충분성을 확인한다.

1. 왜 생겼는가

초기 모형 실패의 상당수는 알고리즘이 아니라 데이터 문제에서 나왔다. 예컨대 연체 후 회수 단계에서 생기는 필드를 변수로 쓰거나, 소득이 비어 있는 신청자가 사라진 표본으로 학습한 모형은 개발 때는 훌륭했으나 운영에서 무너졌다. 그래서 모형 개발 표준 절차에 탐색적 분석(EDA)과 데이터 품질 점검이 독립 단계로 자리 잡았다.

2. 왜 필요한가

4. 어떻게 작동하는가

4-1. 데이터 사전

열마다 이름·자료형·단위·허용 범위·결측 의미·생성 시점·설명을 적는다. "소득"이 만원 단위인지 원 단위인지, 세전인지 세후인지 모르는 채로 분석하면 결과를 해석할 수 없다. 설명서와 실제 값을 비교해 불일치도 기록한다.

4-2. 결측: 세 가지 직관 (Rubin, 1976)

유형 의미 예 삭제의 영향
MCAR 비는 것이 완전 무작위 전산 장애로 임의 행의 일부 값 소실 편향은 적고 정보만 줄어듦
MAR 비는 확률이 관측된 다른 변수와 관련 근속연수가 짧은 사람이 소득을 안 적음 특정 집단이 사라져 편향 가능
MNAR 비는 확률이 비어 있는 값 자체와 관련 소득이 낮은 사람이 소득을 숨김 데이터만으로 확인 불가, 위험

데이터만으로 MCAR/MAR/MNAR 를 확정할 수 없다. 그룹별 결측률 비교는 "무작위가 아니다"를 시사할 수 있을 뿐이다. 처리 원칙은 다음과 같다.

  1. 먼저 왜 비었는지(시스템·입력 절차·업무)를 확인한다.
  2. 결측을 별도 범주/지표로 둘지, 대체할지, 제외할지 정하고 이유를 기록한다.
  3. 대체값(평균·중앙값 등)은 학습 데이터에서만 계산하고 검증·테스트에는 적용만 한다(누수 방지, 단계 8).
  4. 운영에서도 같은 이유로 비는지 모니터링한다.

4-3. 이상치: 오류인가, 실제인가

나이 150 세는 입력 오류일 가능성이 크지만, 소득 10억 원은 실제 극단값일 수 있다. 통계 규칙은 의심 후보를 찾을 뿐이다. 대표적인 IQR 규칙은 다음과 같다.

\[\text{하한}=Q_1-1.5\,\mathrm{IQR},\qquad \text{상한}=Q_3+1.5\,\mathrm{IQR},\qquad \mathrm{IQR}=Q_3-Q_1\]

import numpy as np

x = np.array([20, 22, 25, 27, 30, 31, 35, 38, 40, 41, 300], dtype=float)
q1, q3 = np.percentile(x, [25, 75])          # numpy 기본: 선형 보간
iqr = q3 - q1
low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
print(q1, q3, iqr, low, high, x[(x < low) | (x > high)])
assert (q1, q3, iqr) == (26.0, 39.0, 13.0)
assert (low, high) == (6.5, 58.5)
assert x[(x < low) | (x > high)].tolist() == [300.0]

처리 방식(삭제, 결측 처리, 윈저라이징(상·하한으로 값을 자름), 로그 변환, 비닝)은 업무 판단이다. 비닝(단계 5)은 극단값의 영향을 자연스럽게 줄여 주는 장점이 있다.

4-4. 타깃 누수 점검표

누수(leakage) 는 모형이 운영 시점에는 알 수 없는 정보로 학습하는 것이다(Kaufman et al., 2012).

유형 예 질문
미래 정보 신청 후 3개월 연체 횟수 기준시점 이후에 생기는 값인가?
결과 이후 상태 회수 상태, 채권 매각 여부, 법적 조치 플래그 부도의 결과로 생기는 값인가?
승인 이후 변수 최종 승인 금리·한도 심사 결과가 반영된 값인가? (정책이 이미 위험을 반영)
타깃 파생 타깃을 가공해 만든 열 계산식에 타깃이 들어가는가?
식별자·순서 ID/일련번호가 시간 순서를 담음 키 값이 결과와 관련되는가?
전처리 누수 전체 데이터 평균으로 결측 대체, 전체로 변수 선택 검증·테스트 정보가 학습에 쓰였는가? (단계 8)

경험적 신호: 단일 변수로 비정상적으로 높은 IV·AUROC 가 나오면 누수를 먼저 의심한다. 규칙 기반 경고는 도움이 되지만 최종 판정은 사람이 한다.

import re

def leak_candidates(columns, patterns=("after", "post", "collect", "recover", "writeoff", "status", "result")):
    """열 이름만으로 만든 '의심 후보' 목록. 이름이 안전해 보여도 누수일 수 있으므로 점검표를 별도로 사용한다."""
    return [c for c in columns if any(re.search(p, c, re.I) for p in patterns)]

cols = ["age", "income", "collection_status", "months_after_open", "utilization"]
print(leak_candidates(cols))
assert leak_candidates(cols) == ["collection_status", "months_after_open"]

4-5. 단변량 분석과 타깃별 비교

  • 수치형: 평균·중앙값·분위수·왜도·결측률. 평균과 중앙값이 크게 다르면 치우친 분포다.
  • 범주형: 빈도, 희소 범주(건수가 매우 적은 범주), 범주별 부도율.
  • 타깃별 비교: 부도/정상 집단의 분포 차이, 변수 구간별 부도율.
  • 항상 건수와 이벤트 수를 함께 본다. 건수가 작은 구간의 부도율은 흔들린다(단계 1, 3의 신뢰구간).

4-6. 대표성과 하위집단

전체 표본이 충분해도 지역·연령대·상품별 부도 건수는 부족할 수 있다. 하위집단별 건수와 이벤트 수를 표로 만들고, 부족한 집단은 모형이 불안정할 수 있음을 기록한다. 개발 표본이 운영 모집단을 대표하는지(분포 비교)도 확인한다.

4. 어떻게 작동하는가

4-1. 확률과 베이즈 정리

조건부확률은 \(P(A\mid B)=P(A\cap B)/P(B)\) 이다. 베이즈 정리는 결과에서 원인으로 확률을 뒤집는다.

\[P(D\mid F)=\frac{P(F\mid D)\,P(D)}{P(F\mid D)\,P(D)+P(F\mid \bar D)\,P(\bar D)}\]

숫자 예제. 전체 부도율 \(P(D)=5\%\). 연체이력이 있는 비율은 부도 고객 60%, 정상 고객 20%. 연체이력이 있는 고객이 부도일 확률은?

\[P(D\mid F)=\frac{0.6\times0.05}{0.6\times0.05+0.2\times0.95}=\frac{0.03}{0.22}\approx 13.6\%\]

부도 고객의 60%가 연체이력이 있어도, 그 신호가 있는 사람 대부분은 정상이다(기저율 5% 가 낮기 때문). 기저율(base rate) 을 잊으면 신호를 과대평가한다.

4-2. 모집단·표본·표준오차·신뢰구간

표본의 부도율 \(\hat p=x/n\) 의 표준오차는 \(\sqrt{\hat p(1-\hat p)/n}\) 이다. 표본이 4배가 되면 표준오차는 절반이 된다. 부도가 드물거나 표본이 작을 때는 정규근사 구간이 0 아래로 내려가는 등 불안정하므로 Wilson 구간을 쓴다.

\[\text{center}=\frac{\hat p+\tfrac{z^2}{2n}}{1+\tfrac{z^2}{n}},\qquad \text{half}=\frac{z\sqrt{\tfrac{\hat p(1-\hat p)}{n}+\tfrac{z^2}{4n^2}}}{1+\tfrac{z^2}{n}}\]

예: \(n=100\), \(x=50\), \(z=1.96\) 이면 구간은 약 (40.4%, 59.6%) 이다.

신뢰구간의 올바른 해석

"이 구간 안에 진짜 부도율이 있을 확률이 95%" 가 아니다. 같은 방법으로 표본을 반복해 구간을 만들면 그 구간들의 약 95%가 진짜 값을 포함한다는 뜻이다. 한 번 계산한 구간은 포함하거나 안 하거나 둘 중 하나다.

4-3. 기본 분포

  • 베르누이(\(p\)): 한 건이 부도(1)/정상(0). 평균 \(p\), 분산 \(p(1-p)\).
  • 이항(\(n,p\)): $n$건 중 부도 건수. 평균 \(np\), 분산 \(np(1-p)\). 모니터링에서 "부도 건수가 예상과 다른가"를 검정할 때 쓴다(단계 15).
  • 정규: 표본 평균의 분포가 표본이 클수록 정규에 가까워진다(중심극한정리). 신뢰구간·z 검정의 근거다.

4-4. 공분산·상관

\[\mathrm{Cov}(X,Y)=E[(X-\mu_X)(Y-\mu_Y)],\qquad \rho=\frac{\mathrm{Cov}(X,Y)}{\sigma_X\sigma_Y}\]

상관은 선형 관계의 세기(-1~1)만 본다. 비선형 관계는 단계 4에서 다룬다.

4-5. 가설검정과 p-value

  1. 귀무가설 \(H_0\): "차이 없음/효과 없음". 대립가설 \(H_1\): "차이 있음".
  2. 검정통계량을 계산한다.
  3. p-value = \(H_0\) 가 참이고 검정의 가정이 맞을 때, 관측된 값 이상으로 극단적인 결과가 나올 확률.
  4. p-value ≤ 유의수준 \(\alpha\)(관행적으로 0.05)이면 \(H_0\) 를 기각한다.

p-value가 아닌 것

  • \(H_0\) 가 참일 확률이 아니다.
  • 효과의 크기나 중요성이 아니다.
  • 0.05 라는 경계는 관행이지 자연의 법칙이 아니다(ASA 성명, 2016).

제1종 오류(\(\alpha\)): 효과가 없는데 있다고 말함. 제2종 오류(\(\beta\)): 효과가 있는데 놓침. 검정력 \(=1-\beta\).

4-6. 유의성 ≠ 중요성: 효과크기

부도 집단의 평균 52, 정상 집단의 평균 50, 표준편차 모두 10 이라 하자. 효과크기(Cohen's \(d\))는 \((52-50)/10=0.2\) 로 작다. 그런데 표본 크기에 따라 p-value 는 크게 달라진다.

집단당 표본 수 Welch t p-value (양측)
100 1.414 0.159
10,000 14.14 약 \(3\times10^{-45}\)

같은 작은 차이가 표본이 크면 극도로 "유의"해진다. 그래서 효과크기와 신뢰구간, 사업적 의미를 함께 본다.

4-7. 대표 검정

검정 질문 주요 가정 대안
Welch t-test 두 집단 평균이 다른가 독립, 대략 정규(표본 크면 완화) Mann–Whitney U (순위 기반)
카이제곱 독립성 두 범주형 변수가 관련 있나 독립 관측, 기대빈도 충분(보통 5 이상) Fisher 정확검정
비율 검정/이항검정 부도율이 기준값과 다른가 독립 정확 이항검정

카이제곱 예제. 임차 고객 1,000명 중 부도 120명(12%), 자가 고객 1,000명 중 부도 80명(8%).

부도 정상
임차 120 880
자가 80 920

기대빈도는 부도 \(100\), 정상 \(900\) (각 행). \(\chi^2=\sum \frac{(O-E)^2}{E}=\frac{20^2}{100}+\frac{20^2}{900}+\frac{20^2}{100}+\frac{20^2}{900}\approx 8.89\), 자유도 1, \(p\approx0.0029\).

import numpy as np
from scipy import stats

# 베이즈
p_d, p_f_d, p_f_g = 0.05, 0.6, 0.2
post = p_f_d * p_d / (p_f_d * p_d + p_f_g * (1 - p_d))
print(round(post, 4))
assert abs(post - 0.136364) < 1e-5

# Welch t (요약통계로)
t100, p100 = stats.ttest_ind_from_stats(52, 10, 100, 50, 10, 100, equal_var=False)
t10k, p10k = stats.ttest_ind_from_stats(52, 10, 10000, 50, 10, 10000, equal_var=False)
print(round(t100, 3), round(p100, 3), round(t10k, 2), p10k)
assert abs(t100 - 1.414) < 1e-3 and abs(p100 - 0.159) < 1e-3
assert abs(t10k - 14.14) < 1e-2 and p10k < 1e-40

# 카이제곱 (연속성 보정 없이)
chi2, p, dof, expected = stats.chi2_contingency(np.array([[120, 880], [80, 920]]), correction=False)
print(round(chi2, 2), round(p, 4), dof)
assert abs(chi2 - 8.8889) < 1e-3 and abs(p - 0.0029) < 1e-4 and dof == 1

4-8. 다중검정과 다중공선성은 다른 문제

  • 다중검정: 검정을 여러 번 하면 우연한 "유의"가 늘어난다(단계 14).
  • 다중공선성: 설명변수끼리 상관이 높아 회귀 계수가 불안정해진다(단계 4). 이름이 비슷해도 원인도 해법도 다르다.

5. 가정

  • 독립성: 관측이 서로 독립이어야 대부분의 공식이 맞다. 같은 고객의 여러 행, 같은 시점의 군집은 독립이 아니다.
  • 표본이 모집단에서 무작위로 뽑혔다(또는 편향이 문서화되어 있다).
  • 각 검정의 분포 가정(정규성, 기대빈도 등).
  • 신뢰구간·p-value 는 표본 추출의 불확실성만 반영한다. 데이터 오류·선택 편향·정의 오류는 반영하지 못한다.

6. 한계와 오용

자주 하는 오용

2. 왜 필요한가

  • 상관이 높은 변수를 그대로 넣으면 계수가 불안정해지고 해석이 흔들린다(규제 모형에서 치명적).
  • 교란변수를 놓치면 변수의 진짜 효과를 오해한다.
  • 변수 선택 기준이 문서화되어야 검증자와 감독당국이 왜 이 변수인가를 이해한다.

4. 어떻게 작동하는가

4-1. 상관: 선형 관계의 세기

  • Pearson 상관은 두 변수의 선형 관계를 잰다. 이상치에 민감하다.
  • Spearman 상관은 순위로 바꿔 Pearson 을 계산한다. 단조 관계(항상 증가/감소)면 1 또는 -1 에 가깝다.

숫자 예제. \(x=1,2,3,4,5\), \(y=x^2\) 이면 \(y\) 는 \(x\) 가 늘 때 항상 늘지만 직선은 아니다. Pearson \(=0.981\), Spearman \(=1.0\).

import numpy as np
from scipy import stats

x = np.arange(1, 6)
y = x ** 2
pearson = np.corrcoef(x, y)[0, 1]
spearman = stats.spearmanr(x, y)[0]
print(round(pearson, 3), round(spearman, 3))
assert abs(pearson - 0.981) < 1e-3 and abs(spearman - 1.0) < 1e-12

상관이 0 이어도 관계가 없다는 뜻이 아니다. \(y=x^2\) 를 0 을 중심으로 대칭 구간에서 보면 Pearson 이 0 에 가깝다. 산점도를 먼저 본다.

4-2. 범주형 변수의 연관성

교차표로 범주별 부도율을 보고, 카이제곱 통계량으로 연관성을 요약한다. 표본 크기 영향을 줄인 효과크기가 Cramér's V 이다.

\[V=\sqrt{\frac{\chi^2}{n\,\min(r-1,\,c-1)}}\]

단계 3 의 임차/자가 예제(\(\chi^2=8.89\), \(n=2000\), 2×2 표)에서 \(V=\sqrt{8.89/2000}\approx0.067\) 로, p-value 는 작아도 연관의 세기는 약하다.

4-3. 다중공선성과 VIF

변수 \(X_j\) 를 나머지 설명변수들로 회귀했을 때의 결정계수를 \(R_j^2\) 라 하면

\[\mathrm{VIF}_j=\frac{1}{1-R_j^2}\]

\(R^2=0.9\) 이면 VIF=10 이다. 두 변수만 있고 상관이 \(r\) 이면 VIF \(=1/(1-r^2)\) 이다. \(r=0.95\) 일 때 약 10.3.

VIF 기준은 관행이다

"5 또는 10 이상이면 문제" 라는 기준이 흔히 쓰이지만 보편 법칙이 아니다. 예측 목적이면 공선성이 있어도 예측 성능은 괜찮을 수 있고, 계수 해석과 안정성이 목적일 때 더 문제가 된다. 조건수(condition number) 는 설계행렬의 수치적 불안정성을 한 숫자로 보여 주는 또 다른 진단이다.

import numpy as np

def vif(X):
    """각 열을 나머지 열로 회귀한 R²에서 VIF 계산 (절편 포함, 최소제곱)."""
    X = np.asarray(X, float)
    out = []
    for j in range(X.shape[1]):
        others = np.delete(X, j, axis=1)
        A = np.c_[np.ones(len(X)), others]
        coef, *_ = np.linalg.lstsq(A, X[:, j], rcond=None)
        resid = X[:, j] - A @ coef
        r2 = 1 - resid.var() / X[:, j].var()
        out.append(1 / (1 - r2))
    return np.array(out)

rng = np.random.default_rng(0)
x1 = rng.normal(size=2000)
x2 = x1 + 0.33 * rng.normal(size=2000)      # x1 과 상관 약 0.95
x3 = rng.normal(size=2000)                   # 독립
v = vif(np.c_[x1, x2, x3])
print(np.round(v, 1))
assert 8 < v[0] < 13 and 8 < v[1] < 13 and v[2] < 1.2

4-4. 교란변수와 심슨의 역설

교란변수는 입력 변수와 타깃 모두에 영향을 주어 겉보기 관계를 만든다. 다음은 가상 데이터다(채널 A=온라인, B=지점).

소득 구간 채널 신청 부도 부도율
고소득 A 100 2 2.0%
고소득 B 700 21 3.0%
저소득 A 700 63 9.0%
저소득 B 100 10 10.0%

각 소득 구간 안에서는 A 가 B 보다 부도율이 낮다(2% < 3%, 9% < 10%). 그러나 전체로 합치면 A: 65/800 = 8.125%, B: 31/800 = 3.875% 로 A 가 더 나빠 보인다. A 채널에 저소득 신청이 몰려 있기 때문이다. 이것이 심슨의 역설이다. 전체 부도율만 비교해 "온라인 채널은 위험하다"고 결론내리면 틀린다.

a = [(100, 2), (700, 63)]
b = [(700, 21), (100, 10)]
assert [d / n for n, d in a] == [0.02, 0.09] and [d / n for n, d in b] == [0.03, 0.10]
assert sum(d for _, d in a) / 800 == 0.08125 and sum(d for _, d in b) / 800 == 0.03875

상호작용은 한 변수의 효과가 다른 변수 값에 따라 달라지는 것이다(예: 연체 이력의 영향이 신용한도 구간에 따라 다름). 로지스틱 회귀는 명시하지 않으면 상호작용을 모른다. 트리 모형은 자동으로 포착한다.

4-5. 변수 선정은 다중 기준의 판단이다

기준 질문 예
업무 논리 부호·방향이 상식과 맞는가 연체가 늘수록 위험 증가
가용성 운영 시점에 안정적으로 얻을 수 있나 심사 시점에 확보 불가한 값 제외
데이터 품질 결측·오류·정의 변경이 심하지 않은가 정의가 바뀐 변수는 위험
안정성 기간별 분포·관계가 안정적인가 기간별 IV/부도율 일관성(단계 5, 10)
예측력 단변량·다변량에서 정보가 있는가 IV, 단변량 AUROC
중복성 다른 변수와 정보가 겹치는가 상관, VIF
법·공정성 사용 금지/제한 변수·대리변수 위험은 없는가 민감 속성의 직·간접 사용 검토
설명가능성 고객·감독당국에게 설명할 수 있나 규제 모형에서 특히 중요

단계적 선택(stepwise) 은 자동화되어 편리하지만, 같은 데이터에서 변수를 고르고 p-value 를 보고하면 낙관적 편향이 생긴다. 자동 선택 결과도 위 기준으로 사람이 검토하고, 선택 과정 자체를 검증 데이터에서 재현해야 한다(단계 8).

5. 가정

  • Pearson 상관은 선형·이상치 영향이 적은 관계를 가정한다.
  • VIF 는 선형 모형의 선형 종속성만 잰다.
  • 다변량 효과는 모형이 옳게 지정되었다는 가정(선형성, 포함된 교란변수) 하에서 해석된다.
  • 관측 데이터에서 교란변수를 모두 통제했다는 보장은 없다.

6. 한계와 오용

자주 하는 오용

  • 상관을 인과로 해석한다("이 변수를 올리면 부도가 줄어든다").
  • p-value 만 보고 변수를 선택하거나 제외한다.
  • 상관행렬 하나로 "공선성 없음"을 선언한다(3개 이상 변수의 선형 결합 공선성은 쌍 상관에서 안 보인다).
  • 부도율이 전체로 높은 변수를 "위험 변수"로 판단한다(심슨의 역설).
  • 상관이 높은 변수를 무조건 삭제한다(업무상 둘 다 필요하면 결합하거나 대표 변수를 정한다).

단계 5. 비닝·WOE·IV

연속형 변수를 구간으로 나누고, 구간마다 "얼마나 위험한가"를 로그 비율(WOE)로 바꾼 뒤, 변수 전체의 정보량(IV)을 요약한다. 스코어카드의 재료가 되는 과정이다.

연결 실습: 노트북 05_binning_woe_iv · 코드 creditlab.features.WoeBinner, woe_iv_from_counts, iv_summary · 이 페이지의 손계산을 먼저 해 보자.

학습 목표

  • 비닝이 필요한 이유와 정보 손실의 대가를 설명한다.
  • 등폭·등빈도·업무 기준·트리 기반 비닝을 구분한다.
  • WOE·IV 를 손으로 계산하고 방향 규칙을 고정한다.
  • 단조성·최소 bin 크기·이벤트 수·안정성을 점검한다.
  • 개발 표본에서만 경계를 만들고 다른 표본에는 같은 경계를 적용한다.

1. 왜 생겼는가

로지스틱 회귀는 변수와 로그오즈의 직선 관계를 가정한다. 그러나 나이, 소득, 사용률은 대개 직선이 아니다(예: 사용률이 매우 낮거나 매우 높을 때 모두 위험). 변수를 구간으로 나누면 비선형을 구간별 값으로 흡수할 수 있고, 극단값·결측·이상치도 한 구간으로 다룰 수 있다. 여기에 구간별 위험을 같은 척도(로그 비율) 로 바꾸는 WOE 가 더해져, 서로 다른 변수들을 하나의 로지스틱 모형에 넣기 쉬워졌다. 이 방식은 신용 스코어카드에서 오래 쓰여 왔다.

2. 왜 필요한가

  • 설명 가능하다: "이 구간이면 이 점수"라고 고객·감독당국에게 보여 줄 수 있다.
  • 결측·극단값 처리 규칙이 점수표에 명시된다.
  • WOE 로 바꾼 변수는 단위·분포가 달라도 비교하기 쉽고, 단조 방향을 사전에 검토할 수 있다.
  • IV 로 변수의 전체 정보량을 한 숫자로 요약해 후보를 거를 수 있다.

3. 무엇을 하는가

입력: 연속형/범주형 변수 + 이진 타깃. 출력: ① 구간 경계, ② 구간별 건수·부도율·WOE, ③ 변수 IV.

4. 어떻게 작동하는가

4-1. 비닝 방법

방법 설명 장점 주의
등폭 값 범위를 같은 폭으로 단순 치우친 분포에서 구간이 비어 있음
등빈도 건수가 같도록 분위수로 구간 크기 안정 같은 값이 많으면 경계 중복
업무 기준 정책상 의미 있는 경계(예: 연체 0/1/2+) 설명 쉬움 데이터와 어긋날 수 있음
트리 기반 타깃을 보고 최적 분할 정보 보존 과적합 위험, 단조 제약 필요

원칙: 경계는 개발(학습) 표본에서만 만들고, 검증·테스트·운영에는 그 경계를 그대로 쓴다. 테스트 표본을 보고 경계를 고치면 누수다.

4-2. WOE 정의 — 이 프로그램의 약속

이 프로그램에서는 타깃이 1=부도(bad), 0=정상(good) 이다. 구간 \(i\) 에서

\[\mathrm{WOE}_i=\ln\frac{\text{부도 분포}_i}{\text{정상 분포}_i}=\ln\frac{B_i/B}{G_i/G}\]

여기서 \(B_i, G_i\) 는 구간 \(i\) 의 부도·정상 건수, \(B, G\) 는 전체 부도·정상 건수다. WOE > 0 이면 전체 평균보다 위험한 구간이다. 이렇게 정의하면 WOE 변수로 부도 로그오즈를 모형화할 때 계수가 양수(이상적으로 1 근처)가 된다.

방향 규칙 주의

교재(예: Siddiqi)에서는 \(\ln(\text{good 분포}/\text{bad 분포})\) 를 쓰는 경우가 많다. 부호만 반대다(\(\mathrm{WOE}_\text{교재}=-\mathrm{WOE}_\text{본 프로그램}\)). IV 는 부호와 무관하게 같다. 코드·문서·보고서에서 방향을 하나로 고정하고 적어 둔다.

4-3. IV (Information Value)

\[\mathrm{IV}=\sum_i\left(\frac{B_i}{B}-\frac{G_i}{G}\right)\mathrm{WOE}_i\]

각 항은 \((\text{부도 분포}-\text{정상 분포})\times\ln(\text{비})\) 로 항상 0 이상이다. 구간 간 부도·정상 분포가 다를수록 IV 가 커진다.

손 계산 예제. 정상 9,000건, 부도 1,000건. 변수 "최근 12개월 연체 건수"를 3구간으로 나눈다.

구간 정상 \(G_i\) 부도 \(B_i\) 부도율 정상 분포 부도 분포 WOE IV 기여
0건 6,100 520 7.9% 0.6778 0.5200 -0.2650 0.0418
1건 1,900 260 12.0% 0.2111 0.2600 0.2083 0.0102
2건 이상 1,000 220 18.0% 0.1111 0.2200 0.6831 0.0744
합계 9,000 1,000 10.0% 1 1 0.1264

예를 들어 1건 구간의 WOE 는 \(\ln(0.26/0.2111)=\ln1.2316=0.2083\) 이다. 부도율이 높은 구간일수록 WOE 가 커져 단조 증가한다.

import numpy as np

G = np.array([6100, 1900, 1000])
B = np.array([520, 260, 220])
dist_g, dist_b = G / G.sum(), B / B.sum()
woe = np.log(dist_b / dist_g)                    # 본 프로그램 규칙: ln(부도 분포 / 정상 분포)
iv_terms = (dist_b - dist_g) * woe
print(np.round(woe, 4), np.round(iv_terms, 4), round(iv_terms.sum(), 4))
assert np.allclose(np.round(woe, 4), [-0.2650, 0.2083, 0.6831])
assert np.allclose(np.round(iv_terms, 4), [0.0418, 0.0102, 0.0744])
assert abs(iv_terms.sum() - 0.1264) < 1e-4
assert np.all(np.diff(B / (G + B)) > 0)          # 부도율이 구간 순서대로 증가(단조)

4-4. IV 해석: 관행이지 법칙이 아니다

흔히 IV < 0.02 는 거의 무정보, 0.02~0.1 약함, 0.1~0.3 중간, 0.3~0.5 강함, 0.5 초과는 의심(누수 가능)으로 읽는다. 이는 업계 관행이다.

  • IV 는 구간 수가 많을수록 커지는 경향이 있다(과적합).
  • IV 는 인과 효과나 미래 예측력을 증명하지 않는다. 기간별 안정성을 따로 본다.
  • 표본이 작으면 IV 도 흔들린다. 부도 건수가 적은 구간은 신뢰할 수 없다.

4-5. 0 빈도와 스무딩

어떤 구간에 부도가 0건이면 \(\ln(0)\) 이 되어 WOE 가 \(-\infty\) 다. 해결은 스무딩이다. 예를 들어 모든 구간의 정상·부도 건수에 0.5 를 더해 분포를 계산한다.

import numpy as np

G = np.array([100, 500, 400])
B = np.array([0, 30, 70])
with np.errstate(divide="ignore"):
    raw = np.log((B / B.sum()) / (G / G.sum()))
smooth = np.log(((B + 0.5) / (B + 0.5).sum()) / ((G + 0.5) / (G + 0.5).sum()))
print(raw, np.round(smooth, 3))
assert np.isneginf(raw[0]) and np.all(np.isfinite(smooth))

# 이 프로그램의 구현(creditlab.features.woe_iv_from_counts)과 같은 정의인지 확인
from creditlab.features import woe_iv_from_counts
assert np.allclose(woe_iv_from_counts(B, G, smoothing=0.5)["woe"], smooth)

스무딩 상수(0.5 등)는 선택이며, 어떤 값을 썼는지 문서화한다. 더 나은 방법은 최소 구간 크기와 최소 이벤트 수를 두어 0 빈도가 생기지 않도록 구간을 합치는 것이다.

4-6. 단조성·최소 bin·안정성

  • 단조성: 업무 논리상 한 방향이어야 하는 변수(예: 연체 많을수록 위험)는 구간이 순서대로 부도율이 증가해야 설명이 쉽다. 단조가 깨지면 이유를 설명하거나 구간을 합친다. U자형 변수(사용률 등)는 단조를 강요하지 않는다.
  • 최소 bin 크기: 예를 들어 전체의 5% 이상, 이벤트 N건 이상 같은 내부 기준을 둔다(수치는 정책).
  • 안정성: 개발 기간을 나눠(예: 연도별) 구간별 부도율·WOE 순서가 유지되는지 본다.
  • 범주형: 희소 범주는 합치고, 미지 범주(운영에서 처음 보는 값)에 대한 규칙(별도 구간 또는 WOE 0)을 미리 정한다.
  • 결측: 별도 구간으로 두고 그 구간의 WOE 를 계산한다(결측 의미가 운영에서도 같은지 확인).

단계 6. 로지스틱 회귀의 수학과 해석

확률을 직접 직선으로 맞추지 않고 로그오즈를 직선으로 맞춘다. 계수 하나가 "오즈를 몇 배로 바꾸는가"로 읽힌다는 점이 신용모형의 해석력의 근간이다.

연결 실습: 노트북 06_logistic_regression.ipynb · 코드 creditlab.models(fit_logistic, fit_regularized, select_C_by_cv) · 이 페이지의 코드(NumPy IRLS ↔ scikit-learn 비교)를 직접 실행해 보자.

학습 목표

  • 확률·오즈·로그오즈(logit)를 서로 변환한다.
  • 로지스틱 함수, 최대우도추정, 손실함수, 경사하강법/뉴턴 방법의 직관을 설명한다.
  • 계수·오즈비·절편·기준범주·스케일링·부호를 해석한다.
  • L1/L2 규제, 완전분리, 희소 이벤트 문제를 설명한다.
  • 계수의 신뢰구간·p-value 해석과 한계를 말한다.

1. 왜 생겼는가

타깃이 0/1 일 때 선형회귀 \(p=\beta_0+\beta_1x\) 를 쓰면 예측이 0 미만이나 1 초과가 되고, 오차의 분산이 \(p(1-p)\) 로 달라져 가정이 깨진다. 확률은 0~1 로 묶여 있지만 로그오즈는 \(-\infty\sim+\infty\) 의 값을 가진다. 그래서 로그오즈를 선형으로 모형화하는 로지스틱 회귀가 널리 쓰이게 되었다. 계수가 오즈의 곱셈 효과로 해석되고, 최대우도로 안정적으로 추정되며, 모형이 투명해 규제 환경에 잘 맞는다.

2. 왜 필요한가

  • 규제 로지스틱 CSS 의 중심 모형이다. 점수카드는 이 모형의 계수를 점수로 바꾼 것이다(단계 7).
  • 계수의 부호와 크기가 업무 논리 검토의 대상이다.
  • AI 모형과의 비교에서 기준선(baseline) 역할을 한다.

3. 무엇을 하는가

입력 \(x_1,\dots,x_k\) → 부도확률 \(p\).

\[\ln\frac{p}{1-p}=\beta_0+\beta_1x_1+\cdots+\beta_kx_k\quad\Longleftrightarrow\quad p=\frac{1}{1+e^{-(\beta_0+\sum\beta_jx_j)}}\]

4. 어떻게 작동하는가

4-1. 확률 ↔ 오즈 ↔ 로그오즈

오즈 \(=p/(1-p)\), 로그오즈 \(=\ln(\text{오즈})\).

\(p\) 오즈 로그오즈
0.01 0.0101 -4.5951
0.05 0.0526 -2.9444
0.10 0.1111 -2.1972
0.20 0.25 -1.3863
0.50 1 0
0.90 9 2.1972

\(p=0.5\) 에서 로그오즈는 0 이고, \(p\) 와 \(1-p\) 는 로그오즈의 부호만 바꾼다(대칭).

4-2. 계수의 해석: 오즈비

\(x_j\) 가 1 단위 늘 때 로그오즈가 \(\beta_j\) 만큼 변하므로 오즈는 \(e^{\beta_j}\) 배가 된다(다른 변수는 고정).

\(\beta=0.7\) → \(e^{0.7}=2.0138\). 즉 오즈가 약 2배. 그러나 확률이 2배가 되는 것은 아니다.

시작 확률 시작 오즈 2.0138배 후 오즈 새 확률
5% 0.0526 0.1060 9.6%
50% 1.0 2.0138 66.8%

같은 계수라도 시작 확률이 다르면 확률의 변화량이 다르다. 그래서 계수는 오즈비로, 확률 변화는 구체적 시점에서 설명한다.

import numpy as np

p = np.array([0.01, 0.05, 0.10, 0.20, 0.50, 0.90])
odds = p / (1 - p)
logit = np.log(odds)
assert np.allclose(np.round(logit, 4), [-4.5951, -2.9444, -2.1972, -1.3863, 0.0, 2.1972])

orr = np.exp(0.7)
def after(p0, ratio):
    o = p0 / (1 - p0) * ratio
    return o / (1 + o)
print(round(orr, 4), round(after(0.05, orr), 4), round(after(0.5, orr), 4))
assert abs(orr - 2.0138) < 1e-4
assert abs(after(0.05, orr) - 0.0958) < 1e-4 and abs(after(0.5, orr) - 0.6682) < 1e-4

4-3. 절편·기준범주·스케일링·부호

  • 절편 \(\beta_0\): 모든 변수가 0 일 때의 로그오즈. 변수를 평균으로 중심화하면 "평균 고객"의 로그오즈가 된다.
  • 범주형 변수는 더미(0/1)로 바꾸고 기준범주를 하나 정한다. 계수는 기준범주 대비 효과다. 기준을 바꾸면 계수가 바뀐다(해석이 달라질 뿐 모형은 같다).
  • 스케일링: 나이(수십 단위)와 소득(수만 단위)은 계수 크기를 직접 비교할 수 없다. 표준화하거나 단위를 명시한다.
  • 부호: 업무 논리와 반대면 공선성·표본·정의를 의심한다. WOE 입력(본 프로그램 규칙: 위험할수록 +)이면 계수가 양수·1 근처여야 자연스럽다.

4-4. 최대우도추정(MLE)과 손실함수

각 고객이 부도 \(y_i\in\{0,1\}\), 모형 확률이 \(p_i\) 일 때 우도는 \(\prod p_i^{y_i}(1-p_i)^{1-y_i}\). 로그를 취한 로그우도를 최대화한다.

\[\ell(\beta)=\sum_{i}\big[y_i\ln p_i+(1-y_i)\ln(1-p_i)\big],\qquad \frac{\partial\ell}{\partial\beta}=X^\top(y-p)\]

음의 평균 로그우도가 곧 로그 손실(log loss) 이다. 기울기는 (실제−예측) 를 변수에 곱해 더한 형태라 직관적이다. 예측이 틀릴수록 큰 수정이 일어난다.

  • 경사하강법: 기울기 방향으로 조금씩 이동.
  • 뉴턴/IRLS(반복 재가중 최소제곱): 2차 정보(헤시안 \(X^\top WX\), \(W=\mathrm{diag}\,p_i(1-p_i)\))를 써 빠르게 수렴. statsmodels 가 이 방식이다.
import numpy as np
from sklearn.linear_model import LogisticRegression
from creditlab.data import make_synthetic_credit_data

df = make_synthetic_credit_data(n=4000, seed=42)
X = df[["age", "card_utilization", "num_delinq_12m"]].to_numpy(float)
y = df["default"].to_numpy()
Xs = (X - X.mean(0)) / X.std(0)                       # 표준화: 계수 크기 비교 가능

def fit_irls(X, y, n_iter=25):
    Xb = np.c_[np.ones(len(X)), X]
    beta = np.zeros(Xb.shape[1])
    for _ in range(n_iter):
        p = 1 / (1 + np.exp(-Xb @ beta))
        grad = Xb.T @ (y - p)
        hess = Xb.T @ (Xb * (p * (1 - p))[:, None])
        step = np.linalg.solve(hess, grad)
        beta += step
        if np.abs(step).max() < 1e-10:
            break
    return beta

beta = fit_irls(Xs, y)
# scikit-learn 은 기본이 L2 규제(C=1.0)이므로, 규제 없는 추정과 비교하려면 C=np.inf (1.8 이상; 이전 버전은 penalty=None)
sk = LogisticRegression(C=np.inf, max_iter=2000).fit(Xs, y)
print(np.round(beta, 3), np.round(np.r_[sk.intercept_, sk.coef_[0]], 3))
assert np.abs(beta - np.r_[sk.intercept_, sk.coef_[0]]).max() < 5e-3
assert beta[1] < 0 < beta[2]                           # 나이↑ → 위험↓, 사용률↑ → 위험↑ (생성식과 일치)

라이브러리 API 는 바뀐다

scikit-learn 1.8 에서 penalty 인자가 deprecated 되어 C, l1_ratio 로 규제를 지정한다(C=np.inf = 규제 없음, 1.9.1 문서 확인). 설치된 버전의 공식 문서를 확인하고, 보고서에 버전을 적는다.

4-5. 규제: L2, L1

과적합과 불안정을 줄이려 계수 크기에 벌점을 준다.

\[\min_\beta\;-\ell(\beta)+\lambda\Big(\alpha\|\beta\|_1+\tfrac{1-\alpha}{2}\|\beta\|_2^2\Big)\]

  • L2(릿지): 계수를 0 쪽으로 부드럽게 줄임. 공선성에 안정적. 계수는 0 이 되지 않음.
  • L1(라쏘): 일부 계수를 정확히 0 으로 만들어 변수 선택 효과. 상관 변수 중 하나만 고르는 경향.
  • scikit-learn 의 C 는 규제 세기의 역수(작을수록 강함)다. 규제를 쓰면 계수는 편향되고, p-value 해석이 달라진다.

4-6. 완전분리와 희소 이벤트

어떤 변수 값을 경계로 부도/정상이 완벽히 갈리면(완전분리) 우도는 계수를 키울수록 계속 커져 최대값이 없다. 계수가 매우 크게 나오거나 수렴 경고가 뜬다. 구간 내 부도 0건인 WOE 구간, 소표본 더미에서 흔하다. 대응: 구간 병합, 규제, 변수 제외, Firth 보정 같은 편향 감소 방법.

4-7. 신뢰구간과 p-value

Wald 검정: \(z=\hat\beta/\mathrm{SE}(\hat\beta)\). 95% 구간은 \(\hat\beta\pm1.96\,\mathrm{SE}\) 이고, 오즈비 구간은 양끝에 \(\exp\) 를 씌운다. 표준오차는 헤시안의 역행렬에서 얻는다. p-value 는 계수가 0 인지에 대한 증거일 뿐 변수의 중요도나 예측력이 아니다(단계 3, 4).

statsmodels 로 추론용 결과를, scikit-learn 으로 예측 파이프라인을 만드는 것이 일반적인 역할 분담이다.

# [requires: statsmodels]
import numpy as np
import statsmodels.api as sm

res = sm.Logit(y, sm.add_constant(Xs)).fit(disp=0)
print(res.summary2().tables[1].round(3))
assert np.allclose(res.params, beta, atol=1e-5)       # 위의 NumPy IRLS 와 같은 해

단계 7. 규제형 로지스틱 CSS와 스코어카드

로지스틱 모형이 만든 로그오즈를 "점수"로 바꾸고, 점수를 "등급"으로 묶고, 등급별 부도율을 검토한다. 모형(예측)과 정책(컷오프)은 분리한다.

연결 실습: 노트북 07_scorecard.ipynb · 코드 creditlab.scorecard(ScoreScaling, Scorecard, make_grade_edges, grade_table, cutoff_analysis) · 이 페이지의 점수 변환 코드를 먼저 실행해 보자.

학습 목표

  • WOE → 로지스틱 → 점수카드로 이어지는 구조를 설명한다.
  • 기준점·기준 오즈·PDO 로 점수를 변환하고 점수 ↔ 오즈 ↔ 확률을 검산한다.
  • 점수 방향(높을수록 안전)과 오즈의 정의를 일관되게 유지한다.
  • 점수 구간 등급화 방법(동일 건수·동일 부도율·업무 기준)의 차이를 안다.
  • 등급별 표본 수·부도율·신뢰구간·단조성을 검토한다.
  • 컷오프(정책) 와 예측모형을 구분하고 override·수동심사의 의미를 이해한다.

1. 왜 생겼는가

로지스틱 회귀의 출력(확률, 로그오즈)은 심사 현장에서 쓰기 불편하다. 심사자·영업점·고객에게는 "720점", "3등급" 같은 정수 점수·등급이 익숙하다. 또 "점수가 20점 오를 때마다 위험이 절반이 된다" 같은 일정한 척도가 있으면 점수 의미가 시간이 지나도 일관된다. 이렇게 모형 출력을 운영 가능한 척도로 바꾸려고 스코어카드가 발전했다.

2. 왜 필요한가

  • 설명 가능성: 변수·구간마다 몇 점인지 표로 보여 줄 수 있다(규제 환경의 요구와 맞음).
  • 운영 일관성: 점수의 의미가 고정되면 정책(컷오프·한도·금리)을 점수로 설계할 수 있다.
  • 모니터링: 점수 분포(PSI)와 등급별 부도율을 시간에 따라 추적한다(단계 10).

3. 무엇을 하는가

변수 구간 → WOE → 로지스틱 계수 → 점수(구간별 점수의 합) → 등급 → 등급별 PD

4. 어떻게 작동하는가

4-1. 구조

단계 5 의 WOE 변수 \(W_j\) 를 입력으로 부도 로그오즈 모형을 적합한다.

\[z=\ln\frac{p}{1-p}=\beta_0+\sum_{j=1}^{m}\beta_j W_j\]

WOE 를 쓰는 이유는 각 변수 구간이 독립적으로 점수에 더해지는 표가 되기 때문이다. 장점은 투명성이고, 단점은 비닝으로 인한 정보 손실과 변수 간 상호작용을 직접 표현하지 못한다는 점이다.

4-2. 점수 변환: 기준점·기준 오즈·PDO

점수를 높을수록 안전하게 만들기 위해 좋은:나쁜 오즈(good odds \(=(1-p)/p\))를 쓴다.

\[\mathrm{Score}=\mathrm{Offset}+\mathrm{Factor}\times\ln(\text{odds}_{good}),\qquad \mathrm{Factor}=\frac{\mathrm{PDO}}{\ln 2},\quad \mathrm{Offset}=\mathrm{Score}_0-\mathrm{Factor}\times\ln(\text{odds}_0)\]

  • \(\mathrm{PDO}\)(points to double the odds): 오즈를 2배로 만드는 점수 증가량.
  • \(\text{odds}_0\), \(\mathrm{Score}_0\): 기준 오즈와 그에 대응하는 기준점.

숫자 예제. 기준점 600 에서 good:bad 오즈 50:1, PDO=20 이라 하자.

  • Factor \(=20/\ln2=28.8539\)
  • Offset \(=600-28.8539\times\ln50=600-112.877=487.123\)
good:bad 오즈 점수 부도확률 \(1/(1+\text{odds})\)
25 : 1 580 3.85%
50 : 1 600 1.96%
100 : 1 620 0.99%
200 : 1 640 0.50%

점수가 20점 오를 때마다 오즈가 2배, 부도확률은 대략 절반(정확히는 \(1/(1+2\,\text{odds})\))이 된다.

import math

pdo, base_score, base_odds = 20, 600, 50
factor = pdo / math.log(2)
offset = base_score - factor * math.log(base_odds)
score = lambda odds_good: offset + factor * math.log(odds_good)
pd_from_odds = lambda odds_good: 1 / (1 + odds_good)

print(round(factor, 4), round(offset, 3))
assert abs(factor - 28.8539) < 1e-4 and abs(offset - 487.123) < 1e-3
for odds, s in [(25, 580), (50, 600), (100, 620), (200, 640)]:
    assert abs(score(odds) - s) < 1e-9                 # 20점마다 오즈 2배
assert abs(pd_from_odds(50) - 0.0196) < 1e-4 and abs(pd_from_odds(100) - 0.0099) < 1e-4

4-3. 구간별 점수 배분

모형이 부도 로그오즈 \(z\) 를 주므로 \(\ln(\text{odds}_{good})=-z\) 이고

\[\mathrm{Score}=\mathrm{Offset}-\mathrm{Factor}\times\Big(\beta_0+\sum_j\beta_jW_j\Big)=\sum_{j}\Big[-\mathrm{Factor}\,\beta_jW_{j}-\tfrac{\mathrm{Factor}\,\beta_0-\mathrm{Offset}}{m}\Big]\]

변수 \(j\) 의 구간 \(i\) 점수는 \(-\mathrm{Factor}\,\beta_jW_{ij}\) 에 절편·기준점 몫을 변수 수 \(m\) 으로 나눠 더한 값이다. 점수표는 보통 반올림한 정수 점수를 쓰므로, 반올림 오차가 합산되어 원래 점수와 몇 점 달라질 수 있다 → 검산 필수.

단일 변수 예제. 단계 5 의 연체 건수 3구간(정상 6,100/1,900/1,000, 부도 520/260/220)에서 \(\beta=1\) 이면 모형 오즈가 구간의 실제 오즈와 같아진다(단일 변수·포화 구간). 그 구간의 good 오즈를 위 점수식에 넣으면

구간 good:bad 오즈 점수
0건 11.73 558.2
1건 7.31 544.5
2건 이상 4.55 530.8

변수 하나라 점수 폭이 좁다. 실제 점수카드는 여러 변수의 점수가 합산되어 넓게 퍼진다.

import numpy as np

G, B = np.array([6100, 1900, 1000]), np.array([520, 260, 220])
odds_good = G / B
scores = offset + factor * np.log(odds_good)       # 앞 코드의 factor/offset
print(np.round(odds_good, 2), np.round(scores, 1))
assert np.allclose(np.round(scores, 1), [558.2, 544.5, 530.8])
assert np.all(np.diff(scores) < 0)                 # 위험한 구간일수록 점수가 낮다

4-4. 점수 구간과 등급화

방식 설명 장점 주의
동일 건수 같은 인원씩 등급별 표본 안정 부도율 간격이 불규칙
동일 부도율 간격 인접 등급 부도율이 비슷하게 벌어짐 해석 직관적 희소 등급 발생 가능
업무 기준 정책·상품 요건 반영 운영 편리 통계적 근거 약할 수 있음
최적화(규칙 기반) 변별력·단조·최소 건수 제약 객관적 개발 표본 과적합 가능

등급 검토 항목: ① 등급별 건수·부도 건수, ② 등급별 부도율과 신뢰구간(Wilson), ③ 단조성(등급이 나빠질수록 부도율 증가), ④ 인접 등급 구분 가능성(구간이 겹치면 합치는 것을 검토), ⑤ 등급별 PD 추정치(장기 평균·보수성 반영은 단계 15).

import numpy as np
import pandas as pd
from creditlab.data import default_rate_ci, make_synthetic_credit_data

df = make_synthetic_credit_data(n=8000, seed=7)
# 설명용 단순 점수: 위험할수록 낮은 점수. (실제 점수는 로지스틱 계수로 만든다)
risk = 2.0 * df["card_utilization"] + 0.6 * df["num_delinq_12m"] - 0.03 * df["age"]
df["score"] = 600 - 40 * (risk - risk.mean()) / risk.std()
df["grade"] = pd.qcut(df["score"], q=5, labels=["E", "D", "C", "B", "A"])   # 동일 건수 5등급 (A=가장 안전)
rows = []
for g, sub in df.groupby("grade", observed=True):
    lo, hi = default_rate_ci(sub["default"])
    rows.append({"grade": g, "n": len(sub), "bad": int(sub["default"].sum()), "rate": sub["default"].mean(), "ci_low": lo, "ci_high": hi})
table = pd.DataFrame(rows).sort_values("grade")   # A → E (가장 안전 → 가장 위험)
print(table.round(4).to_string(index=False))
assert table["n"].sum() == len(df) and (table["ci_low"] <= table["rate"]).all()
assert table["rate"].is_monotonic_increasing                         # A→E 로 갈수록 부도율 증가

4-5. 모형 vs 정책: 컷오프, override

  • 모형은 점수를 낸다. 컷오프는 "몇 점 미만은 거절/심사 강화" 같은 정책이다. 컷오프는 승인율, 기대손실, 수익, 위험선호, 규제·고객 보호 정책 등을 반영해 사업이 정한다(단계 12 임계값 선택).
  • Override: 심사자가 점수와 다르게 결정하는 것. 사유를 기록하고 비율을 모니터링한다. 모형이 못 보는 정보가 있으면 정당할 수 있으나 남용되면 모형의 효과가 사라진다.
  • Reject/수동심사: 점수가 경계 구간이면 사람 심사로 보내는 설계가 흔하다.
  • 모형의 성능과 정책 성과(손익, 승인율)는 따로 평가한다(단계 15).

5. 가정

  • 로지스틱 모형이 로그오즈를 합리적으로 설명한다(WOE 변환 후 선형 근사).
  • 점수–오즈 관계가 시간이 지나도 유지된다(점수의 의미가 안정적).
  • 개발 모집단과 적용 모집단이 충분히 비슷하다(단계 1).
  • 등급별 부도율 순서가 미래에도 유지된다.

자주 하는 오용

  • 점수 방향(높을수록 안전/위험)과 오즈 정의(good:bad vs bad:good)를 섞어 쓴다.
  • 정수 반올림 후 검산을 안 해서 점수와 확률이 어긋난다.
  • 등급을 "부도율이 좋아 보이게" 개발 표본에 맞춰 과도하게 최적화한다.
  • 컷오프를 모형 성능의 일부로 취급한다(승인율이 바뀌면 모형이 나빠진 것처럼 오해).

단계 8. Train/Validation/Test, 교차검증과 누수 방지

모형의 성적은 "처음 보는 데이터"에서만 의미가 있다. 데이터를 어떻게 나누고, 전처리를 어디에서 하며, 테스트를 몇 번 보느냐가 결과의 신뢰성을 정한다.

연결 실습: Phase 4 노트북(예정) · 이 페이지의 코드로 누수 있는/없는 파이프라인을 직접 비교해 보자.

학습 목표

  • 학습/검증/테스트 집합의 역할을 구분한다.
  • 무작위 분할, 시간 기준 분할, 그룹 분할, 층화 분할을 상황에 맞게 고른다.
  • 교차검증과 nested CV 가 해결하는 문제를 설명한다.
  • 전처리·비닝·변수 선택·스케일링을 파이프라인 안에서 fit 해야 하는 이유를 보인다.
  • 데이터 누수의 전형적 패턴을 열거하고 점검표를 만든다.

1. 왜 생겼는가

모형을 만든 데이터로 성능을 재면 항상 좋아 보인다. 모형은 외운 것일 수도 있기 때문이다(과적합). 그래서 보지 않은 데이터로 평가하는 분할이 필요해졌다. 그런데 분할만 하면 끝이 아니다. 전처리·변수 선택·하이퍼파라미터 조정이 평가 데이터의 정보를 몰래 쓰면 분할의 의미가 사라진다. 이것이 누수(leakage)다. 교차검증은 데이터가 적을 때 분할의 불안정성을 줄이려는 방법이다.

2. 왜 필요한가

  • 운영에서 기대할 성능을 추정하려면 평가가 운영과 닮아야 한다.
  • 규제·검증 환경에서는 독립 테스트(표본 외, 시점 외) 결과를 요구한다.
  • 하이퍼파라미터를 조정하는 순간, 같은 평가 데이터를 다시 쓰면 조정에 쓰인 데이터가 된다.

3. 무엇을 하는가

집합 용도 몇 번 보는가
학습(train) 모형 파라미터·전처리·비닝 학습 계속
검증(validation) 모형 선택, 하이퍼파라미터, 조기 종료 여러 번 (그래서 점점 오염됨)
테스트(test) 최종 성능 보고 원칙적으로 한 번

4. 어떻게 작동하는가

4-1. 분할 방식

방식 언제 주의
무작위 시간 의존이 없고 행이 독립 신용 데이터는 시간·고객 의존이 있어 낙관적
층화(stratified) 부도가 드물 때 분할마다 부도율이 비슷해짐
시간 기준(out-of-time) 미래에 적용할 모형 가장 현실적. 경기·정책 변화 포착
그룹(고객·계좌·가구) 같은 고객이 여러 행 같은 고객이 train 과 test 에 동시에 있으면 누수

핵심 원칙: 미래에 배포할 모형의 성능은 시간 기준 분할로 추정한다. 무작위 분할 성능만으로 실제 미래 성능을 보장할 수 없다.

이벤트 수 점검: 10,000건, 부도율 3% → 부도 300건. 5-fold CV 에서 검증 fold 당 부도 60건. 부도율 1% 면 총 100건, fold 당 20건이라 지표가 크게 흔들린다. 분할 전에 분할별 이벤트 수를 계산한다.

4-2. 교차검증(CV)

데이터를 \(K\) 조각으로 나눠 돌아가며 한 조각을 검증, 나머지를 학습으로 쓰고 \(K\) 개 성능의 평균과 산포를 본다. 장점: 적은 데이터로도 안정적 추정. 주의: 시간·그룹 구조를 무시하면 누수(→ StratifiedKFold, GroupKFold, TimeSeriesSplit).

Nested CV: 하이퍼파라미터 선택(안쪽 CV)과 성능 추정(바깥쪽 CV)을 분리한다. 안쪽 CV 점수를 최종 성능이라고 보고하면, 선택에 쓴 데이터로 평가한 낙관적 값이다(Cawley & Talbot, 2010).

4-3. 전처리는 학습 데이터에서만 fit

스케일링·결측 대체·비닝·변수 선택은 모두 데이터에서 무언가를 배우는 단계다. 이 단계들이 검증/테스트 데이터를 보면 안 된다. scikit-learn Pipeline 은 교차검증의 각 fold 마다 학습 구간에서만 fit 하게 해 준다.

고전적 실험(ESL §7.10.2). 타깃과 아무 관계 없는 무작위 변수 1,000개로 만든 데이터 100건이 있다. 전체 데이터로 "타깃과 가장 관련 있어 보이는" 변수 20개를 먼저 고른 뒤 교차검증하면 성능이 좋아 보인다. 그러나 선택을 파이프라인 안에서 하면 성능은 우연 수준으로 돌아온다.

import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
X = rng.normal(size=(100, 1000))          # 전부 무작위 잡음 변수
y = rng.integers(0, 2, 100)               # 타깃도 무작위: 진짜 예측력은 0(AUROC≈0.5)
cv = StratifiedKFold(5, shuffle=True, random_state=0)

X_sel = SelectKBest(f_classif, k=20).fit_transform(X, y)      # ✗ 전체 데이터(타깃 포함)로 변수 선택
leaky = cross_val_score(LogisticRegression(max_iter=1000), X_sel, y, cv=cv, scoring="roc_auc").mean()

pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000))
correct = cross_val_score(pipe, X, y, cv=cv, scoring="roc_auc").mean()   # ✓ 각 fold 의 학습 구간에서만 선택
print(round(leaky, 3), round(correct, 3))
assert leaky > 0.8 and correct < 0.7 and leaky - correct > 0.2

의미 없는 데이터에서 AUROC ≈ 0.94 가 나온다. 이것이 누수의 위력이다. 현실의 누수는 더 미묘해서(비닝·IV 선택·결측 대체) 같은 방식으로 과대평가가 슬며시 들어온다.

4-4. 시간 기준 분할 구현

import pandas as pd
from creditlab.data import make_synthetic_credit_data

df = make_synthetic_credit_data(n=6000, seed=3).sort_values("application_date")
cut_dev, cut_val = df["application_date"].quantile([0.6, 0.8])
train = df[df["application_date"] <= cut_dev]                       # 과거 60%
valid = df[(df["application_date"] > cut_dev) & (df["application_date"] <= cut_val)]   # 다음 20%
test = df[df["application_date"] > cut_val]                          # 가장 최근 20% (마지막에 한 번)
print(len(train), len(valid), len(test))
assert train["application_date"].max() <= valid["application_date"].min()
assert valid["application_date"].max() <= test["application_date"].min()
assert len(train) + len(valid) + len(test) == len(df)
assert set(train["application_id"]).isdisjoint(test["application_id"])

5. 가정

  • 테스트 데이터가 운영에서 만날 데이터를 대표한다.
  • 분할된 집합들이 서로 독립이다(고객·시간 누수 없음).
  • 검증 성능이 선택 때문에 낙관적일 수 있음을 인정하고, 최종 테스트로 확인한다.
  • 이벤트 수가 지표 추정에 충분하다.

6. 한계와 오용

자주 하는 오용

  • 테스트 성능이 마음에 안 들어 모형을 고치고 다시 테스트한다 → 테스트가 검증이 되어 낙관적.
  • 무작위 분할 성능을 운영 성능처럼 보고한다.
  • CV 점수의 평균만 보고하고 산포(fold 간 차이)를 보지 않는다.
  • 시계열 구조가 있는데 KFold(shuffle=True) 를 쓴다.
  • 시간 분할인데 가장 최근 기간이 다른 경기 국면이라 성능이 다르게 나온 것을 모형 문제로만 해석한다(환경 변화일 수 있음).
  • 이벤트가 적을 때 검증 fold 를 너무 잘게 나눈다.

모형이 "좋다"는 말은 지표마다 다른 뜻이다. 순위를 잘 맞히는가(변별력), 확률 값이 맞는가(보정), 특정 컷오프에서 어떤 오류가 나는가(분류 성능)를 따로 본다.

연결 실습: Phase 4 노트북(예정) · 코드 creditlab.evaluation(예정) · 이 페이지의 8건 예제를 손으로 먼저 풀어 보자.

학습 목표

  • 혼동행렬과 정확도·정밀도·재현율·특이도·F1 을 계산하고 임계값에 의존함을 설명한다.
  • ROC·AUROC, Gini = 2×AUROC − 1, KS, PR-AUC 의 정의와 해석을 말한다.
  • log loss, Brier score, calibration curve 로 확률의 질을 평가한다.
  • AR(Accuracy Ratio)의 정의를 명시적으로 고정해야 하는 이유를 설명한다.
  • 순위 변별력과 확률 정확성의 차이를 구분한다.
  • 부트스트랩 신뢰구간과 기간별 성능 변화를 본다.

1. 왜 생겼는가

초기에는 정확도(맞힌 비율)로 모형을 평가했다. 그러나 부도가 1% 인 데이터에서 "모두 정상"이라고 예측하면 정확도 99% 다. 불균형 데이터에서는 정확도가 쓸모 없고, 임계값과 무관하게 순위를 평가하는 ROC/AUROC 와 KS, 확률을 직접 평가하는 log loss·Brier·보정이 필요해졌다. 신용 분야에서는 CAP 곡선과 Accuracy Ratio(AR)도 쓰인다.

2. 왜 필요한가

  • 모형 선택·비교·승인의 근거가 지표다.
  • 지표마다 약점이 있어 하나로 결론내리면 틀린다.
  • 변별력이 좋아도 확률이 틀리면 PD 로 쓸 수 없고(보정), 확률이 맞아도 순위가 약하면 심사에 도움이 안 된다.

3. 무엇을 하는가

질문 지표
누가 더 위험한지 순위를 잘 매기나? AUROC, Gini, AR, KS
드문 부도 중에서 얼마나 잘 찾나? PR-AUC(평균 정밀도), 재현율@k
예측 확률이 실제 부도율과 맞나? calibration curve, Brier, log loss
특정 컷오프에서 오류는? 혼동행렬, 정밀도·재현율
성능이 시간에 안정적인가? 기간별 AUROC/KS, 신뢰구간

4. 어떻게 작동하는가

4-1. 8건 손계산 예제

부도(1) 3건의 위험점수: 0.9, 0.7, 0.4 / 정상(0) 5건: 0.8, 0.5, 0.3, 0.2, 0.1. 점수가 높을수록 위험하다.

혼동행렬 (임계값 0.45 이상이면 "부도 예측")

예측 부도 예측 정상
실제 부도 TP=2 (0.9, 0.7) FN=1 (0.4)
실제 정상 FP=2 (0.8, 0.5) TN=3 (0.3, 0.2, 0.1)
  • 정확도 \(=(2+3)/8=0.625\)
  • 정밀도 \(=TP/(TP+FP)=2/4=0.5\)
  • 재현율(민감도) \(=TP/(TP+FN)=2/3=0.667\)
  • 특이도 \(=TN/(TN+FP)=3/5=0.6\)
  • F1 \(=2TP/(2TP+FP+FN)=4/7=0.571\)

임계값을 바꾸면 모든 숫자가 바뀐다. 임계값은 사업 정책(단계 12)이므로 혼동행렬 지표는 정책과 함께 해석한다.

AUROC

AUROC = 무작위로 뽑은 (부도, 정상) 한 쌍에서 부도의 점수가 더 높을 확률(동점은 0.5).

부도 3 × 정상 5 = 15 쌍. 부도 0.9 는 5쌍 모두 이김(5), 0.7 은 0.8 에게 지고 나머지 4쌍을 이김(4), 0.4 는 0.3, 0.2, 0.1 을 이김(3) → \(12/15=0.8\).

Gini와 AR

\[\mathrm{Gini}=2\times\mathrm{AUROC}-1=0.6\]

완벽한 모형은 1, 무작위는 0 이다. AR(Accuracy Ratio) 는 CAP 곡선으로 정의된다.

\[\mathrm{AR}=\frac{\text{CAP 곡선과 무작위선 사이 면적}}{\text{완벽 모형 CAP 곡선과 무작위선 사이 면적}}\]

표준 CAP 정의에서는 \(\mathrm{AR}=2\times\mathrm{AUROC}-1\) 이 수학적으로 성립한다(Engelmann, Hayden & Tasche, 2003). 그러나 조직·문헌별로 AR 계산이 다를 수 있다(표본 구성, 동점 처리, 점수 대신 등급 단위로 계산하는 경우의 계단형 곡선, 부호 방향 등). 따라서 이 프로그램은 AR 을 자동으로 Gini 로 환산하지 않고, 프로젝트 설정에 산식·방향·분모를 명시하도록 한다.

KS 통계량

부도 누적분포와 정상 누적분포의 최대 차이: \(\mathrm{KS}=\max_s|F_{bad}(s)-F_{good}(s)|\).

임계값(이상) 부도 중 비율(TPR) 정상 중 비율(FPR) 차이
0.9 0.333 0.0 0.333
0.8 0.333 0.2 0.133
0.7 0.667 0.2 0.467
0.5 0.667 0.4 0.267
0.4 1.0 0.4 0.6
0.3 1.0 0.6 0.4
0.2 1.0 0.8 0.2

KS = 0.6 (임계값 0.4 에서). KS 는 한 점의 차이만 보고, 표본 구성·부도율에 영향받을 수 있다.

Brier score와 log loss

점수를 확률로 보면,

\[\mathrm{Brier}=\frac1n\sum(p_i-y_i)^2,\qquad \mathrm{LogLoss}=-\frac1n\sum\big[y_i\ln p_i+(1-y_i)\ln(1-p_i)\big]\]

예제: Brier \(=1.49/8=0.18625\), log loss \(\approx0.5458\). 둘 다 작을수록 좋다. log loss 는 틀린 확신(예: 정상에 0.99 부여)을 크게 벌한다.

import numpy as np
from sklearn.metrics import average_precision_score, brier_score_loss, log_loss, roc_auc_score, roc_curve

s = np.array([0.9, 0.7, 0.4, 0.8, 0.5, 0.3, 0.2, 0.1])
y = np.array([1, 1, 1, 0, 0, 0, 0, 0])

auc = roc_auc_score(y, s)
fpr, tpr, _ = roc_curve(y, s)
ks = (tpr - fpr).max()
print(round(auc, 3), round(2 * auc - 1, 3), round(ks, 3), round(brier_score_loss(y, s), 5), round(log_loss(y, s), 4))
assert abs(auc - 0.8) < 1e-12 and abs(2 * auc - 1 - 0.6) < 1e-12 and abs(ks - 0.6) < 1e-12
assert abs(brier_score_loss(y, s) - 0.18625) < 1e-12 and abs(log_loss(y, s) - 0.5458) < 1e-4

# 쌍 비교로 직접 계산한 AUROC (정의 확인)
bad, good = s[y == 1], s[y == 0]
pairs = [(b > g) + 0.5 * (b == g) for b in bad for g in good]
assert abs(np.mean(pairs) - auc) < 1e-12

# 임계값 0.45 혼동행렬
pred = (s >= 0.45).astype(int)
tp, fp = int(((pred == 1) & (y == 1)).sum()), int(((pred == 1) & (y == 0)).sum())
fn, tn = int(((pred == 0) & (y == 1)).sum()), int(((pred == 0) & (y == 0)).sum())
assert (tp, fp, fn, tn) == (2, 2, 1, 3)
assert abs(2 * tp / (2 * tp + fp + fn) - 4 / 7) < 1e-12

4-2. 불균형과 정확도, PR-AUC

부도율 1% 에서 "모두 정상" 예측은 정확도 99%, 재현율 0%. PR 곡선은 정밀도–재현율 관계를 보여 주며 무작위 모형의 정밀도가 부도율(기저율)과 같다. 부도가 드물수록 ROC 는 낙관적으로 보일 수 있어, 상위 위험군 선별이 중요한 문제에서는 PR-AUC(평균 정밀도)를 함께 본다(Saito & Rehmsmeier, 2015). 단, PR-AUC 는 부도율에 따라 값 자체가 달라지므로 다른 부도율의 데이터끼리 직접 비교하지 않는다.

4-3. 변별력과 보정은 다르다

  • 변별력(discrimination): 위험 순서를 맞히는 능력. AUROC/KS/Gini.
  • 보정(calibration): "예측 5%"인 고객들의 실제 부도율이 5% 인가. Brier, log loss, 보정곡선.

모든 예측확률에 2를 곱해도 순서는 같아 AUROC 는 변하지 않지만 확률은 틀어진다. PD 모형은 둘 다 필요하다.

보정곡선(reliability diagram): 예측확률을 구간으로 나누어 각 구간의 평균 예측과 실제 부도율을 비교한다. 대각선이면 잘 보정된 것이다. 구간 요약 지표로 ECE(기대 보정 오차) 등이 쓰이지만 구간 정의에 민감하다.

import numpy as np
from sklearn.calibration import calibration_curve
from sklearn.linear_model import LogisticRegression
from creditlab.data import make_synthetic_credit_data

df = make_synthetic_credit_data(n=6000, seed=11).sort_values("application_date")
feats = ["age", "card_utilization", "num_delinq_12m", "employment_years"]
train, test = df.iloc[:4000], df.iloc[4000:]
model = LogisticRegression(C=np.inf, max_iter=2000).fit(train[feats], train["default"])
p = model.predict_proba(test[feats])[:, 1]
frac_pos, mean_pred = calibration_curve(test["default"], p, n_bins=5, strategy="quantile")
print(np.round(mean_pred, 3), np.round(frac_pos, 3))
assert len(frac_pos) == len(mean_pred) <= 5
assert abs(p.mean() - test["default"].mean()) < 0.03   # 전체 평균 수준은 크게 어긋나지 않음

4-4. 신뢰구간과 기간별 변화

지표는 표본에서 계산된 추정치다. 같은 모형도 표본이 달라지면 AUROC 가 달라진다. 부트스트랩(복원추출 반복)으로 구간을 만들고, 시점별로 성능이 어떻게 변하는지 함께 본다. 이벤트가 적으면 구간이 넓다.

import numpy as np
from sklearn.metrics import roc_auc_score

rng = np.random.default_rng(0)
y_t, p_t = test["default"].to_numpy(), p
auc_hat = roc_auc_score(y_t, p_t)
boot = []
for _ in range(300):
    idx = rng.integers(0, len(y_t), len(y_t))
    if y_t[idx].min() == y_t[idx].max():        # 한 클래스만 있으면 AUROC 정의 불가 → 건너뜀
        continue
    boot.append(roc_auc_score(y_t[idx], p_t[idx]))
lo, hi = np.percentile(boot, [2.5, 97.5])
print(round(auc_hat, 3), (round(lo, 3), round(hi, 3)))
assert lo < auc_hat < hi

4-5. 정의되지 않는 경우

테스트 구간에 부도가 0건이거나 정상이 0건이면 AUROC 는 정의되지 않는다. 숫자를 억지로 만들지 말고 "계산 불가(한 클래스만 존재)" 로 표시한다.

5. 가정

  • 평가 데이터가 운영 데이터를 대표한다(단계 8).
  • 레이블(부도)이 정의대로 정확히 붙어 있다.
  • AUROC/KS 는 표본의 순위 정보만 쓰므로 보정 오류를 못 본다.
  • 신뢰구간(부트스트랩)은 관측이 독립이라고 가정한다(고객 군집이면 군집 부트스트랩).

6. 한계와 오용

자주 하는 오용

  • 정확도·정밀도 등 혼동행렬 지표를 임계값을 말하지 않고 비교한다.
  • AUROC 하나로 "좋은 모형"을 선언한다. 보정이 틀리거나 상위 위험군에서 약할 수 있다(Hand, 2009: AUROC 의 비용 가정 문제).
  • 부도율이 다른 두 표본의 KS·PR-AUC 를 직접 비교한다.
  • AR 을 정의 확인 없이 Gini 와 같다고 보고한다.
  • 개발 표본(학습) 지표를 성능으로 보고한다.
  • 지표 차이가 0.002 인데 "개선"이라고 한다(신뢰구간과 단계 14 참조).

지표 보는 것 장점 약점

9. 지식 확인

Q1. AUROC 0.8 이면 Gini 는? 무작위 모형의 AUROC 와 Gini 는?

정답 보기

Gini \(=2\times0.8-1=0.6\). 무작위는 AUROC 0.5, Gini 0.

Q2. 모든 예측확률에 2를 곱했다. AUROC, Brier 는 어떻게 되는가?

정답 보기

AUROC 는 변하지 않고(순서 동일), Brier 와 log loss 는 일반적으로 나빠진다(확률이 틀어짐). 변별력과 보정은 다르다.

Q3. 부도율 0.5% 인 데이터에서 정확도 99.5% 모형을 얻었다. 의미 있는 성과인가?

정답 보기

"모두 정상" 예측만으로도 99.5% 가 나온다. 정확도는 의미가 없다. 재현율·정밀도·PR-AUC·AUROC 와 보정을 본다.

Q4. 테스트 기간에 부도가 한 건도 없다. AUROC 를 어떻게 보고하는가?

정답 보기

"계산 불가(정의되지 않음: 한 클래스만 존재)"로 보고한다. 기간을 합치거나 더 긴 관찰을 기다린다.

Q5 (계산). 부도 점수 {0.8, 0.3}, 정상 점수 {0.6, 0.2, 0.1}. AUROC 를 쌍 비교로 계산하라.

정답 보기

6쌍. 0.8 은 3쌍 모두 이김(3), 0.3 은 0.6 에게 지고 0.2, 0.1 을 이김(2) → \(5/6\approx0.833\).

실습 과제: 합성 데이터에서 시간 기준 분할 후 로지스틱 모형을 적합하고, 테스트 구간 AUROC/Gini/KS/Brier/log loss 와 보정곡선을 구하라. 분기별 AUROC 와 부트스트랩 구간을 표로 쓰고, 5등급의 등급별 부도율을 함께 제시하라. AR 의 정의를 문장으로 명시하라.

  • 기준기간·비교기간·고정된 bin 경계의 중요성을 설명한다.
  • 0 빈도 처리와 표본 수가 PSI 에 미치는 영향을 안다.
  • 데이터 분포 변화(covariate shift) 와 관계 변화(concept drift) 를 구분한다.
  • 변수별 PSI, 점수 PSI, 등급 구성비, 부도율 모니터링을 설계한다.
  • PSI 임계값이 관행적 경보 기준임을 이해한다.

1. 왜 생겼는가

대출 모형은 몇 년씩 쓰인다. 그 사이 고객 구성이 바뀌고(신규 채널, 상품 변화), 경기가 변하고, 데이터 입력 방식이 바뀐다. 성능을 직접 보려면 부도 결과가 나올 때까지 수개월~1년 기다려야 한다. 그래서 결과를 기다리지 않고 입력·점수 분포의 변화를 먼저 감지하는 지표로 PSI(Population Stability Index)가 쓰이게 되었다.

2. 왜 필요한가

  • 입력 분포가 크게 변하면 모형이 본 적 없는 영역에서 쓰이는 것이므로 성능이 떨어질 수 있다.
  • 성능 지표(AUROC, 부도율)는 지연된다. PSI 는 즉시 계산된다.
  • 시스템 오류(항목 누락, 단위 변경, 결측 급증)를 조기에 발견한다.

3. 무엇을 하는가

기준(expected, 보통 개발 표본) 분포와 비교(actual, 현재 표본) 분포를 같은 구간(bin) 으로 나누어 비교한다.

4. 어떻게 작동하는가

4-1. 정의

구간 \(i\) 의 기준 비율 \(e_i\), 비교 비율 \(a_i\) 일 때

\[\mathrm{PSI}=\sum_{i=1}^{k}(a_i-e_i)\,\ln\frac{a_i}{e_i}\]

각 항은 항상 0 이상이고, 분포가 같으면 0 이다. PSI 는 두 방향 KL 발산의 합이다: \(\mathrm{PSI}=D_{KL}(a\|e)+D_{KL}(e\|a)\) (대칭).

손계산 예제. 5개 구간.

구간 기준 \(e_i\) 현재 \(a_i\) \((a_i-e_i)\ln(a_i/e_i)\)
1 0.10 0.08 0.0045
2 0.20 0.17 0.0049
3 0.40 0.38 0.0010
4 0.20 0.24 0.0073
5 0.10 0.13 0.0079
합 0.0255 (반올림 합 0.0256) 
import numpy as np

e = np.array([0.10, 0.20, 0.40, 0.20, 0.10])
a = np.array([0.08, 0.17, 0.38, 0.24, 0.13])
terms = (a - e) * np.log(a / e)
psi = terms.sum()
kl = lambda p, q: (p * np.log(p / q)).sum()
print(np.round(terms, 4), round(psi, 4))
assert np.allclose(np.round(terms, 4), [0.0045, 0.0049, 0.0010, 0.0073, 0.0079])
assert abs(psi - 0.0255) < 5e-5
assert abs(psi - (kl(a, e) + kl(e, a))) < 1e-12        # 대칭 KL 의 합

4-2. 해석 기준은 관행이다

실무에서는 PSI < 0.10 이면 안정, 0.10~0.25 면 주의(조사), 0.25 초과면 큰 변화로 보는 경보 기준이 널리 쓰인다. 이는 통계 법칙이 아니라 업계 관행이고, 구간 수·표본 크기·변수 성격에 따라 적절한 값이 달라진다. 기준은 조직이 정하고 문서화한다.

4-3. bin 경계는 기준기간에서 한 번 정해 고정

  • 구간은 기준기간(개발 표본) 에서 분위수(예: 10분위)나 비닝 구간으로 만들고, 현재 표본에도 같은 경계를 적용한다. 현재 표본으로 경계를 다시 만들면 항상 비슷한 분포로 보여 변화가 사라진다.
  • 경계 양끝은 열어 둔다(−∞, +∞) 그래야 새로운 극단값도 들어간다.
  • 범주형 변수는 범주별 비율을 쓰고, 새 범주는 별도 구간으로 둔다. 결측도 별도 구간.
import numpy as np
import pandas as pd
from creditlab.data import make_synthetic_credit_data

def psi_from_samples(expected, actual, bins=10, eps=1e-4):
    """기준(expected) 분위수 경계를 고정해 actual 에 적용한 PSI. 0 비율은 eps 로 바닥을 둔다."""
    edges = np.unique(np.quantile(expected, np.linspace(0, 1, bins + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    e = pd.cut(pd.Series(expected), edges).value_counts(sort=False).to_numpy() / len(expected)
    a = pd.cut(pd.Series(actual), edges).value_counts(sort=False).to_numpy() / len(actual)
    e, a = np.clip(e, eps, None), np.clip(a, eps, None)
    return float(((a - e) * np.log(a / e)).sum())

df = make_synthetic_credit_data(n=8000, seed=21).sort_values("application_date")
dev, now = df.iloc[:4000], df.iloc[4000:]
print("같은 분포의 두 시점:", round(psi_from_samples(dev["card_utilization"], now["card_utilization"]), 4))

shifted = now["card_utilization"] + 0.15                      # 사용률이 전반적으로 0.15 올랐다고 가정(분포 이동 주입)
psi_shift = psi_from_samples(dev["card_utilization"], shifted)
print("분포 이동 주입 후:", round(psi_shift, 4))
assert psi_from_samples(dev["card_utilization"], now["card_utilization"]) < 0.05
assert psi_shift > 0.25

4-4. 0 빈도와 표본 수

  • 비교기간에 어떤 구간이 비면 \(\ln(0)\) 때문에 PSI 가 무한대가 된다 → 작은 값(eps)으로 바닥을 두거나 인접 구간과 합친다. eps 선택에 따라 값이 크게 달라질 수 있으므로 방법을 문서화한다.
  • 표본이 작으면 PSI 는 우연만으로도 커진다. 분포 변화가 전혀 없어도 기대 PSI 는 대략 \((k-1)\,(1/n_e+1/n_a)\) 이다. \(k=10\), \(n_e=n_a=1{,}000\) 이면 약 0.018. 표본이 작은 월별 모니터링에서는 임계값을 표본 수에 맞게 해석한다.
import numpy as np

rng = np.random.default_rng(5)
k, n = 10, 1000
vals = []
for _ in range(400):
    exp = rng.normal(size=n)
    act = rng.normal(size=n)                     # 같은 분포에서 뽑은 두 표본: 진짜 변화는 0
    vals.append(psi_from_samples(exp, act, bins=k))
print(round(float(np.mean(vals)), 4), "이론 근사:", (k - 1) * (2 / n))
assert 0.010 < np.mean(vals) < 0.030

4-5. 분포 변화 vs 관계 변화

변화 의미 PSI 로 보이나 예
공변량 이동(covariate shift) 입력 \(X\) 의 분포가 변함, \(P(Y\mid X)\) 는 그대로 보임 신규 채널로 젊은 고객 증가
개념 변화(concept drift) \(X\) 와 \(Y\) 의 관계가 변함 안 보일 수 있음 경기 침체로 같은 소득도 위험해짐
사전확률 변화(prior shift) 부도율 자체가 변함 입력엔 안 보임 전반적 부도율 상승

PSI 가 작아도 관계가 변했을 수 있고, PSI 가 커도 모형이 여전히 잘 작동할 수 있다. 그래서 성능 지표(AUROC/KS)·보정·등급별 부도율을 같이 본다. PSI 하나만으로 모형 안정성을 판정할 수 없다.

4-6. 모니터링 설계

대상 지표 주기 경보 후 조치
변수 분포 변수별 PSI(CSI 라고도 함) 월/분기 원인 조사(데이터 오류? 모집단 변화?)
점수 분포 점수 PSI, 등급 구성비 월 정책·한도 영향 검토
변별력 AUROC/KS(성과 관찰 후) 분기/반기 재개발 검토
보정 등급별 예측 PD vs 실제 부도율 분기/반기 재보정 검토(단계 12, 15)
데이터 품질 결측률, 범위 오류 매 배치 시스템 점검

경보 → 조사 → 조치 → 재검토의 책임과 기한을 사전에 정해 둔다.

  • 구간 경계와 정의가 시간에 걸쳐 동일하다.
  • 변화의 방향·크기는 표본 변동보다 충분히 크다.

트리는 "조건 분기"로 데이터를 쪼개고, 부스팅은 그런 작은 트리를 앞선 모형의 실수를 고치는 방향으로 계속 더한다. 성능은 올라가지만 설명 가능성과 안정성의 비용을 치른다.

학습 목표

  • 불순도(지니)와 분할 이득을 손으로 계산한다.
  • 단일 트리의 과적합과 배깅(랜덤포레스트)·부스팅의 차이를 설명한다.
  • 그래디언트 부스팅의 "잔차(그래디언트)를 적합하는 반복"을 구현으로 확인한다.
  • 학습률·트리 수·깊이의 상호작용과 조기 종료를 이해한다.
  • 단조성 제약이 왜 신용 모형에서 중요한지 말한다.

1. 왜 생겼는가

로지스틱 회귀는 변수의 효과가 가산적·선형적이라고 가정한다. 현실에는 상호작용(소득이 낮고 동시에 사용률이 높을 때만 위험)과 비선형이 있다. 트리는 이를 자동으로 잡는다. 단일 트리는 불안정해서 배깅(Breiman, 2001)과 부스팅(Friedman, 2001)이 발전했고, 이후 XGBoost(2016), CatBoost(2018) 등이 정형 데이터의 표준 도구가 되었다.

2. 왜 필요한가

  • 비선형·상호작용을 수작업 변수 설계 없이 포착한다.
  • 결측과 범주형 처리가 상대적으로 쉽다.
  • 로지스틱 모형 대비 변별력 개선 여지가 있다. 단, 개선폭은 데이터마다 다르며 작을 수도 있다.

4-1. 지니 불순도와 분할 이득 (손계산)

노드의 부도율 \(p\) 에 대해 지니 \(G=2p(1-p)\) (이진 분류). 10건(부도 4, 정상 6)을 변수 \(x\) 로 분할한다고 하자.

  • 부모: \(p=0.4\), \(G=2(0.4)(0.6)=0.48\)
  • 왼쪽 노드 5건(부도 1, 정상 4): \(p=0.2\), \(G=0.32\)
  • 오른쪽 노드 5건(부도 3, 정상 2): \(p=0.6\), \(G=0.48\)
  • 자식 가중평균: \(0.5(0.32)+0.5(0.48)=0.40\)
  • 분할 이득 = 0.48 − 0.40 = 0.08
def gini(bad, good):
    n = bad + good
    p = bad / n
    return 2 * p * (1 - p)

parent = gini(4, 6)
left, right = gini(1, 4), gini(3, 2)
child = (5 / 10) * left + (5 / 10) * right
gain = parent - child
print(round(parent, 2), round(left, 2), round(right, 2), round(child, 2), round(gain, 2))
assert abs(parent - 0.48) < 1e-12 and abs(left - 0.32) < 1e-12 and abs(right - 0.48) < 1e-12
assert abs(gain - 0.08) < 1e-12

트리는 모든 변수·모든 분할점 후보 중 이득이 가장 큰 곳을 고르는 일을 반복한다(탐욕적). 정지 조건(최대 깊이, 잎 최소 표본)이 없으면 학습 데이터를 완벽 암기한다.

4-3. 배깅과 부스팅

  • 랜덤포레스트: 서로 다른 부트스트랩 표본·변수 부분집합으로 깊은 트리 여러 개를 독립적으로 만들고 평균 → 분산 감소.
  • 그래디언트 부스팅: 현재 예측의 손실 그래디언트의 반대 방향을 얕은 트리로 적합해 학습률 \(\eta\) 만큼 더한다.

\[F_m(x)=F_{m-1}(x)+\eta\,h_m(x),\qquad h_m \approx -\frac{\partial L}{\partial F}\Big|_{F_{m-1}}\]

로그 손실에서 \(-\partial L/\partial F = y-p\) (잔차)이다. 아래는 이를 직접 구현해 sklearn 과 비슷한 성능이 나오는지 확인한다.

import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import roc_auc_score
from sklearn.tree import DecisionTreeRegressor

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

X, y = Xtr.to_numpy(), ytr.to_numpy().astype(float)
F = np.full(len(y), np.log(y.mean() / (1 - y.mean())))        # 초기값: 로그 오즈
trees, eta = [], 0.1
for _ in range(100):
    resid = y - sigmoid(F)                                      # 음의 그래디언트 = 잔차
    t = DecisionTreeRegressor(max_depth=3, min_samples_leaf=50, random_state=0).fit(X, resid)
    F += eta * t.predict(X)        # (단순화: 잎 값 뉴턴 보정 생략)
    trees.append(t)

def predict(Xn):
    f = np.full(len(Xn), np.log(y.mean() / (1 - y.mean())))
    for t in trees:
        f += eta * t.predict(Xn)
    return sigmoid(f)

mine = roc_auc_score(yte, predict(Xte.to_numpy()))
ref = GradientBoostingClassifier(n_estimators=100, learning_rate=0.1, max_depth=3, min_samples_leaf=50, random_state=0).fit(Xtr, ytr)
ref_auc = roc_auc_score(yte, ref.predict_proba(Xte)[:, 1])
print(round(mine, 3), round(ref_auc, 3))
assert mine > 0.6 and abs(mine - ref_auc) < 0.03

4-5. 단조성 제약

연체 횟수가 늘수록 위험이 줄어드는 구간이 모형에 생기면 심사자와 규제 당국은 수용하기 어렵다. 부스팅 라이브러리는 변수별 단조 제약(예: 연체횟수↑ → 위험 비감소)을 지원한다. 제약은 약간의 성능을 포기하는 대신 설명 가능성·정책 일관성을 얻는다. sklearn 의 HistGradientBoostingClassifier(monotonic_cst=...) 로 확인한다.

import numpy as np

cst = [0] * len(feats)

hgb = HistGradientBoostingClassifier(max_depth=4, max_iter=150, learning_rate=0.1, monotonic_cst=cst, random_state=0).fit(Xtr, ytr)

grid = Xte.copy().iloc[:300]

for v in range(0, 6):

4-6. SHAP

SHAP 은 게임이론의 Shapley 값을 이용해 각 변수가 개별 예측을 기준값에서 얼마나 밀어 올리거나 내렸는지 가산적으로 분해한다.

\[f(x)=\phi_0+\sum_{j}\phi_j(x)\]

트리 모형에는 정확·빠른 알고리즘(TreeSHAP)이 있다. 그러나 SHAP 은 모형이 어떻게 예측하는지의 설명이지 현실에서 무엇이 원인인지가 아니다. 상관된 변수가 있으면 기여도가 나뉘고, 배경 데이터 선택에 따라 값이 달라진다. 규제 설명(불이익 사유 통지) 용도로는 승인된 방법론 문서가 필요하다.

# [requires: shap]
import numpy as np
import shap

explainer = shap.TreeExplainer(ref)
sv = explainer.shap_values(Xte.iloc[:200])
base = explainer.expected_value
raw = ref.decision_function(Xte.iloc[:200])
assert np.allclose(base + sv.sum(axis=1), raw, atol=1e-6)    # 가산성: 기준값 + 기여도 합 = 모형 출력(로그오즈)

단계 12. 튜닝·앙상블·보정

튜닝은 "검증 데이터에 맞춰 설정을 고르는 일"이므로, 그 데이터는 이미 오염되었다. 최종 성능은 한 번도 쓰지 않은 데이터로만 말한다. 그리고 순위가 좋은 모형도 확률이 틀리면 PD 가 아니다.

연결 실습: Phase 5 노트북(예정).

학습 목표

  • 학습·검증·테스트 세트의 역할을 구분하고 테스트 오염을 설명한다.
  • 시간 순서를 지키는 교차검증(Time-series split)과 그리드/랜덤 탐색을 구현한다.
  • 앙상블(평균·스태킹)의 이점과 위험을 말한다.
  • Platt scaling·Isotonic 보정을 적용하고 보정 전후를 비교한다.
  • 임계값(컷오프)이 모형이 아니라 정책임을 설명한다.

1. 왜 생겼는가

모형 설정(하이퍼파라미터)을 바꿀 때마다 성능을 확인하면, 우리는 확인에 쓴 데이터에 유리한 설정을 고르게 된다. 이것이 선택 편향이다. 이를 막기 위해 데이터를 역할별로 나누고(학습/검증/테스트), 교차검증으로 안정적 추정을 얻는다. 부스팅·신경망은 확률을 과신하거나 과소신하는 경향이 있어 사후 보정 기법(Platt 2000, Zadrozny & Elkan 2002)이 쓰인다.

2. 왜 필요한가

  • 튜닝 없이는 부스팅이 과적합하고, 튜닝만 하면 검증 데이터에 과적합한다.
  • PD 는 확률 값 자체가 자본·충당금·가격에 쓰인다 → 보정이 필수다.
  • 컷오프는 승인율·손실률의 경영 의사결정이다.

import numpy as np

for depth, lr, n_iter in grid:
    scores = []
    for tr_idx, va_idx in tscv.split(Xdev):
        m = HistGradientBoostingClassifier(max_depth=depth, learning_rate=lr, max_iter=n_iter,
                                           min_samples_leaf=50, random_state=0).fit(Xdev.iloc[tr_idx], ydev.iloc[tr_idx])
        scores.append(roc_auc_score(ydev.iloc[va_idx], m.predict_proba(Xdev.iloc[va_idx])[:, 1]))
    rows.append(((depth, lr, n_iter), float(np.mean(scores))))
rows.sort(key=lambda r: -r[1])
best_params, best_cv = rows[0]
print(best_params, round(best_cv, 4))

final = HistGradientBoostingClassifier(max_depth=best_params[0], learning_rate=best_params[1], max_iter=best_params[2],
                                       min_samples_leaf=50, random_state=0).fit(Xdev, ydev)

rank_avg = (rankdata(p_lr) + rankdata(p_gb)) / 2
print({"lr": round(roc_auc_score(yte, p_lr), 4), "gb": round(roc_auc_score(yte, p_gb), 4),
       "avg": round(roc_auc_score(yte, rank_avg), 4)})
assert roc_auc_score(yte, rank_avg) > min(roc_auc_score(yte, p_lr), roc_auc_score(yte, p_gb)) - 0.02

4-4. 보정: Platt 과 Isotonic

  • Platt scaling: 모형 점수 \(s\) 에 대해 \(p=\sigma(a s+b)\) 를 적합. 단순·안정, 왜곡이 시그모이드형일 때 적합.
  • Isotonic: 단조 증가 계단함수. 유연하지만 표본이 적으면 과적합.
  • 보정은 보정 전용 데이터(학습에 쓰지 않은 구간)에서 적합한다.

부도율이 전체적으로 이동했을 때(prior shift)의 단순 절편 보정도 있다: 로그 오즈에 상수를 더해 평균 예측을 목표 부도율에 맞춘다.

import numpy as np
from sklearn.calibration import calibration_curve
from sklearn.isotonic import IsotonicRegression
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import brier_score_loss

# 보정 전용 구간: 개발 데이터의 마지막 1500건을 따로 떼고, 모형은 그 앞에서만 학습
fit_part, cal_part = dev.iloc[:5500], dev.iloc[5500:]
base = HistGradientBoostingClassifier(max_depth=5, learning_rate=0.1, max_iter=400, min_samples_leaf=20, random_state=0)
base.fit(fit_part[feats].fillna(-1), fit_part["default"])           # 과적합하기 쉬운 설정(과신 유도)
s_cal = base.predict_proba(cal_part[feats].fillna(-1))[:, 1]
s_te = base.predict_proba(Xte)[:, 1]

logit = lambda p: np.log(np.clip(p, 1e-6, 1 - 1e-6) / (1 - np.clip(p, 1e-6, 1 - 1e-6)))
platt = LogisticRegression(C=np.inf, max_iter=1000).fit(logit(s_cal).reshape(-1, 1), cal_part["default"])
p_platt = platt.predict_proba(logit(s_te).reshape(-1, 1))[:, 1]
iso = IsotonicRegression(out_of_bounds="clip", y_min=0, y_max=1).fit(s_cal, cal_part["default"])
p_iso = iso.predict(s_te)

for name, p in [("보정 전", s_te), ("Platt", p_platt), ("Isotonic", p_iso)]:
    print(name, "Brier", round(brier_score_loss(yte, p), 5), "AUROC", round(roc_auc_score(yte, p), 4))
assert brier_score_loss(yte, p_platt) <= brier_score_loss(yte, s_te) + 1e-9    # 과신 모형은 보정 후 Brier 가 낮아진다
assert abs(roc_auc_score(yte, p_platt) - roc_auc_score(yte, s_te)) < 1e-9      # 단조 변환: 순위 불변

Platt 은 단조 변환이므로 AUROC 가 변하지 않는다. 보정은 확률의 값만 고친다. Isotonic 은 동점(계단)을 만들어 AUROC 가 약간 변할 수 있다.

4-5. 임계값은 정책이다

승인 컷오프 \(t\) 에서 기대 손익은 대략

\[\text{기대이익}(t)=\sum_{i:\,p_i<t}\big[(1-p_i)\,m-p_i\,L\big]\]

(\(m\) = 정상 고객의 건당 마진, \(L\) = 부도 시 손실). 마진과 손실은 사업이 정한다. 같은 모형도 마진·손실 가정이 바뀌면 최적 컷오프가 바뀐다.

import numpy as np

m_gain, loss = 1.0, 8.0            # 가정: 정상 1단위 이익, 부도 8단위 손실
p = p_platt
order = np.sort(p)
profits = []
cands = np.quantile(p, np.linspace(0.3, 1.0, 36))
for t in cands:
    approve = p < t
    profits.append(((1 - p[approve]) * m_gain - p[approve] * loss).sum())
best_t = cands[int(np.argmax(profits))]
print("최적 컷오프(확률)", round(float(best_t), 4), "승인율", round(float((p < best_t).mean()), 3))
# 기대이익이 양수인 고객(1-p)m - pL > 0  ⇔  p < m/(m+L) 만 승인하는 것이 이론적 최적
theory = m_gain / (m_gain + loss)
print("이론 컷오프 m/(m+L) =", round(theory, 4))
assert abs(theory - 1 / 9) < 1e-12

보정된 확률에서 이론 최적 컷오프는 \(p<m/(m+L)\) 이다. 이 공식은 확률이 잘 보정되어 있을 때만 성립하므로 보정이 정책의 전제다.

단계 13. GAN과 합성데이터

합성데이터는 "진짜 데이터의 대용품"이 아니라 "진짜 데이터의 통계적 그림자"다. 그림자가 얼마나 닮았는지(충실도), 그림자로 학습해도 현실에서 통하는지(유용성), 원본 개인을 드러내지 않는지(프라이버시)를 각각 확인해야 한다.

연결 실습: 이 프로그램의 creditlab.data.synthetic 은 규칙으로 만든 교육용 가상 데이터이다. 이 단계의 합성데이터는 실제 데이터를 학습해서 만든 데이터를 다룬다. 둘은 다르다.

학습 목표

  • 합성데이터를 쓰는 이유(프라이버시, 희소 부도, 데이터 공유)와 한계를 설명한다.
  • 가우시안 코퓰러 방식의 합성기를 직접 구현한다.
  • GAN(CTGAN 계열)의 구조와 표 형태 데이터에서의 어려움을 이해한다.
  • 충실도·유용성(TSTR)·프라이버시 세 축으로 합성데이터를 평가한다.
  • 소수 클래스 오버샘플링의 데이터 누수를 재현해 피한다.

1. 왜 생겼는가

신용 데이터는 개인정보라서 공유·외부 위탁·교육 사용이 어렵다. 부도는 드물어 학습 표본이 부족하다. 그래서 원본의 통계적 성질을 유지하는 인공 데이터를 만들려는 시도가 생겼다. 초기에는 SMOTE(Chawla et al., 2002) 같은 보간 기반 오버샘플링, 통계적 모형(코퓰러), 이후 GAN(Goodfellow et al., 2014)과 표 형태 전용 CTGAN(Xu et al., 2019)이 나왔다.

2. 왜 필요한가

  • 외부 연구자·교육·테스트 환경에 실데이터 없이 줄 수 있는 후보다.
  • 희소 사건의 학습 보조(단, 효과는 데이터마다 다르고 보장되지 않음).
  • 시나리오·스트레스 데이터를 만든다.

3. 무엇을 하는가

방식 핵심 비고
단순 오버샘플링 소수 클래스 행 복제 정보 증가 없음, 누수 위험
SMOTE 이웃 사이 보간 표형 혼합 변수에 약함
가우시안 코퓰러 주변분포 + 상관구조 단순·설명 쉬움, 비선형 의존 약함
CTGAN/TVAE 신경망으로 결합분포 학습 튜닝·평가 어려움, 프라이버시 별도 검증

4. 어떻게 작동하는가

4-1. 가우시안 코퓰러 합성기 (직접 구현)

  1. 각 수치 열을 순위 → 표준정규 점수로 바꾼다.
  2. 변환된 열들의 상관행렬을 추정한다.
  3. 다변량 정규분포에서 표본을 뽑는다.
  4. 각 열을 원래 분포의 경험적 분위수로 되돌린다.

주변분포(각 열의 모양)와 선형적 상관을 보존한다.

import numpy as np
import pandas as pd
from scipy.stats import norm, rankdata
from creditlab.data import make_synthetic_credit_data

def fit_copula(df):
    """수치 열 DataFrame 에서 (상관행렬, 정렬된 원자료) 를 추정."""
    z = np.column_stack([norm.ppf(rankdata(df[c]) / (len(df) + 1)) for c in df.columns])
    return np.corrcoef(z, rowvar=False), {c: np.sort(df[c].to_numpy()) for c in df.columns}

def sample_copula(corr, sorted_cols, n, seed):
    rng = np.random.default_rng(seed)
    z = rng.multivariate_normal(np.zeros(corr.shape[0]), corr, size=n)
    u = norm.cdf(z)
    out = {}
    for j, (c, srt) in enumerate(sorted_cols.items()):
        out[c] = np.quantile(srt, u[:, j])
    return pd.DataFrame(out)

real = make_synthetic_credit_data(n=8000, seed=51).dropna()
cols = ["age", "income_10k", "loan_amount_10k", "employment_years", "card_utilization", "num_delinq_12m", "inquiries_6m", "default"]
real = real[cols].reset_index(drop=True)
r_train, r_hold = real.iloc[:5000], real.iloc[5000:]
corr, srt = fit_copula(r_train)
synth = sample_copula(corr, srt, 5000, seed=0)
synth["default"] = (synth["default"] > 0.5).astype(int)      # 이진 열은 반올림해 복원(단순화)

print(round(r_train["default"].mean(), 3), round(synth["default"].mean(), 3))
print(r_train[["age", "income_10k", "card_utilization"]].mean().round(2).to_dict())
print(synth[["age", "income_10k", "card_utilization"]].mean().round(2).to_dict())
assert abs(r_train["age"].mean() - synth["age"].mean()) < 1.0               # 주변분포(평균) 보존
diff = np.abs(np.corrcoef(r_train.drop(columns="default"), rowvar=False) - np.corrcoef(synth.drop(columns="default"), rowvar=False)).max()
print("상관행렬 최대 차이", round(float(diff), 3))
assert diff < 0.1

4-2. 충실도: 닮았는가

  • 열별: 평균·분위수·KS 통계량, 범주 비율
  • 열 사이: 상관행렬 차이, 목표변수와의 관계(예: 변수 구간별 부도율)
  • 목표변수와의 관계가 약해지기 쉽다: 코퓰러가 비선형·상호작용을 놓치면 \(P(Y\mid X)\) 가 흐려진다.

4-3. 유용성: TSTR

TSTR(Train on Synthetic, Test on Real): 합성데이터로 모형을 학습하고 진짜 보류 데이터로 평가해 TRTR(진짜로 학습·진짜로 평가)과 비교한다.

import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

feat = [c for c in cols if c != "default"]
def fit_eval(train_df):
    m = make_pipeline(StandardScaler(), LogisticRegression(C=1.0, max_iter=2000)).fit(train_df[feat], train_df["default"])
    return roc_auc_score(r_hold["default"], m.predict_proba(r_hold[feat])[:, 1])

trtr, tstr = fit_eval(r_train), fit_eval(synth)
print("TRTR", round(trtr, 3), "TSTR", round(tstr, 3))
assert tstr > 0.55                     # 합성데이터로도 순위 정보는 일부 전달됨
assert tstr < trtr + 0.03              # 합성이 실데이터보다 눈에 띄게 좋을 수는 없다

TSTR 이 TRTR 에 크게 못 미치면 합성기가 \(P(Y\mid X)\) 를 못 잡은 것이다.

4-4. 프라이버시: 닮음과 복제는 다르다

합성기가 학습 행을 외워서 내보내면 개인정보가 노출된다. 가장 가까운 원본과의 거리(DCR, Distance to Closest Record)로 확인한다. 합성 행이 원본과 정확히 같으면 복제다.

import numpy as np
from scipy.spatial import cKDTree

feat_cols = feat
scale = r_train[feat_cols].std().replace(0, 1)
tree = cKDTree((r_train[feat_cols] / scale).to_numpy())

def dcr(df):
    d, _ = tree.query((df[feat_cols] / scale).to_numpy(), k=1)
    return d

copula_dcr = dcr(synth)
naive = r_train.sample(1000, random_state=0)          # '합성'이랍시고 원본 행을 그대로 재표집
naive_dcr = dcr(naive)
holdout_dcr = dcr(r_hold)
print("복제기 최소거리", float(naive_dcr.min()), "| 코퓰러 최소거리", round(float(copula_dcr.min()), 4),
      "| 보류데이터 중앙값", round(float(np.median(holdout_dcr)), 3))
assert naive_dcr.max() == 0                     # 복제는 거리 0 → 즉시 탐지
assert copula_dcr.min() > 0

DCR>0 이라고 안전한 것은 아니다. 희귀한 극단 행(소득이 매우 높은 사람 등)은 가까운 합성 행으로 재식별될 수 있고, 합성 모형이 특정 개인의 존재 여부를 드러내는지(멤버십 추론) 평가해야 한다. 형식적 보장은 차등 프라이버시(DP) 학습 같은 별도 기법이 필요하다. 합성데이터 ≠ 자동 익명화.

# G: 잡음 z -> 합성 행,  D: 행 -> '진짜일 확률'
for step in range(n_steps):
    real_batch = sample(real_data)
    fake_batch = G(z=random_noise())
    # 판별자: 진짜는 1, 가짜는 0 으로 분류하도록 학습
    loss_D = bce(D(real_batch), 1) + bce(D(fake_batch), 0)
    # 생성자: 판별자를 속이도록 학습
    loss_G = bce(D(fake_batch), 1)

표 형태 데이터에서의 어려움: 연속·범주 혼합, 극단 비대칭 분포(소득), 불균형 범주(부도). CTGAN 은 모드 특이 정규화와 조건부 샘플링으로 이를 다룬다. 학습이 불안정하고 모드 붕괴(일부 패턴만 생성)가 일어날 수 있어 평가가 필수다.

단계 14. 가설검정·p-value·DeLong·다중검정

"AUROC 가 0.003 올랐다"는 것만으로는 개선이 아니다. 그 차이가 표본이 달라져도 반복될 변동보다 큰지를 따져야 한다. 검정은 그 질문에 답하는 도구이고, p-value 는 흔히 오해된다.

연결 실습: Phase 6 노트북(예정). 이 페이지의 코드만으로 DeLong 검정을 직접 구현한다.

학습 목표

  • 귀무가설·유의수준·p-value 의 정의와 p-value 가 아닌 것을 말한다.
  • 순열검정으로 p-value 를 직접 계산하고 t-검정과 비교한다.
  • 같은 데이터로 평가한 두 모형의 AUROC 를 DeLong 검정으로 비교한다.
  • 다중검정 문제와 Bonferroni·BH(FDR) 보정을 계산한다.
  • 통계적 유의성과 실무적 유의성을 구분한다.

1. 왜 생겼는가

표본은 우연히 흔들린다. 그 흔들림 안의 차이를 "개선"이라 부르면 우연을 성과로 착각한다. Fisher 와 Neyman–Pearson 이 가설검정 틀을 만들었고, 신용 분야에서는 같은 고객으로 평가한 두 모형의 AUROC 비교가 상관되어 있다는 점을 반영한 DeLong 검정(DeLong et al., 1988)이 표준 도구가 되었다.

2. 왜 필요한가

  • 모형 교체는 비용이 크다. 우연한 개선에 근거해 교체하면 안 된다.
  • 변수·모형·하이퍼파라미터를 많이 시도할수록 우연히 좋아 보이는 것이 반드시 나온다.
  • 결과를 신뢰구간·효과 크기와 함께 보고해야 의사결정이 가능하다.

3. 무엇을 하는가

질문 도구
두 집단 평균이 다른가? t-검정, 순열검정
두 모형 AUROC 가 다른가(같은 표본)? DeLong
여러 개를 동시에 검정했을 때 Bonferroni, Holm, BH
차이가 얼마나 큰가? 신뢰구간, 효과 크기

4. 어떻게 작동하는가

4-1. 가설검정의 구조

  1. 귀무가설 \(H_0\): "차이가 없다"를 가정.
  2. 검정통계량 계산.
  3. p-value = \(H_0\) 가 참이라고 가정할 때 관측값만큼 또는 더 극단적인 결과가 나올 확률.
  4. \(p<\alpha\)(관행 0.05)이면 \(H_0\) 를 기각.

p-value 는 "귀무가설이 참일 확률"이 아니다. 효과의 크기도, 효과가 중요한지도 알려 주지 않는다. 표본이 매우 크면 사소한 차이도 유의해진다. p>0.05 는 "차이가 없다"의 증명이 아니라 "차이를 못 찾았다"이다.

4-2. 순열검정으로 p-value 직접 만들기

\(H_0\) 가 참이면 집단 라벨은 교환 가능하다. 라벨을 무작위로 섞어 통계량의 분포를 만들고, 관측값이 그 분포에서 얼마나 극단인지 본다.

import numpy as np
from scipy import stats

rng = np.random.default_rng(0)
a = rng.normal(0.0, 1.0, 60)
b = rng.normal(0.5, 1.0, 60)            # 진짜 평균 차이 0.5

obs = b.mean() - a.mean()
pooled = np.concatenate([a, b])
perm = np.empty(5000)
for i in range(5000):
    rng.shuffle(pooled)
    perm[i] = pooled[60:].mean() - pooled[:60].mean()
p_perm = (np.abs(perm) >= abs(obs)).mean()
p_t = stats.ttest_ind(b, a, equal_var=False).pvalue
print(round(obs, 3), "순열 p =", round(p_perm, 4), "Welch t p =", round(p_t, 4))
assert abs(p_perm - p_t) < 0.05

4-3. DeLong 검정 (직접 구현)

AUROC 는 U-통계량이다. 부도 \(i\) 에 대한 구조 성분 \(V_{10,i}=\frac1n\sum_j\psi(s_i,s_j)\) (\(j\) 는 정상), 정상 \(j\) 에 대한 \(V_{01,j}=\frac1m\sum_i\psi(s_i,s_j)\) 로 분산과 공분산을 추정한다. 여기서 \(\psi(x,y)=1\) (x>y), \(0.5\) (x=y), \(0\) (x<y). 두 모형이 같은 고객을 평가하므로 공분산을 반영한다.

\[Z=\frac{\widehat{AUC}_1-\widehat{AUC}_2}{\sqrt{\operatorname{Var}_1+\operatorname{Var}_2-2\operatorname{Cov}}}\]

import numpy as np
from scipy import stats

def psi_matrix(pos, neg):
    d = pos[:, None] - neg[None, :]
    return (d > 0) + 0.5 * (d == 0)

def delong_components(y, scores):
    pos, neg = scores[y == 1], scores[y == 0]
    k = psi_matrix(pos, neg)
    return k.mean(axis=1), k.mean(axis=0), k.mean()     # V10 (부도별), V01 (정상별), AUC

def delong_test(y, s1, s2):
    m, n = int((y == 1).sum()), int((y == 0).sum())
    v10_1, v01_1, a1 = delong_components(y, s1)
    v10_2, v01_2, a2 = delong_components(y, s2)
    S10 = np.cov(np.vstack([v10_1, v10_2]))
    S01 = np.cov(np.vstack([v01_1, v01_2]))
    S = S10 / m + S01 / n
    var = S[0, 0] + S[1, 1] - 2 * S[0, 1]
    z = (a1 - a2) / np.sqrt(var)
    return a1, a2, z, 2 * stats.norm.sf(abs(z))

# 단계 9 의 8건 예제: AUROC 0.8 확인 (구조 성분 평균이 AUC)
s = np.array([0.9, 0.7, 0.4, 0.8, 0.5, 0.3, 0.2, 0.1]); y8 = np.array([1, 1, 1, 0, 0, 0, 0, 0])
v10, v01, auc = delong_components(y8, s)
print(np.round(v10, 3), np.round(v01, 3), auc)
assert abs(auc - 0.8) < 1e-12 and abs(v10.mean() - 0.8) < 1e-12 and abs(v01.mean() - 0.8) < 1e-12
assert np.allclose(v10, [1.0, 0.8, 0.6])

import numpy as np
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from creditlab.data import make_synthetic_credit_data

4-4. 다중검정

20개 변수를 각각 5% 수준으로 검정하면, 모두 귀무가설이 참이어도 최소 하나가 유의할 확률이

\[1-(1-0.05)^{20}\approx 0.6415\]

이다. 해결책:

  • Bonferroni: \(\alpha/m\) 로 기각(보수적, FWER 통제).
  • Holm: Bonferroni 의 단계적 개선.
  • Benjamini–Hochberg(BH): 거짓 발견 비율(FDR)을 통제. p 를 오름차순 정렬해 \(p_{(k)}\le \frac{k}{m}q\) 를 만족하는 가장 큰 k 까지 기각.
import numpy as np

assert abs((1 - 0.95**20) - 0.6415) < 1e-4

def bh_reject(pvals, q=0.05):
    p = np.asarray(pvals); m = len(p)
    order = np.argsort(p)
    passed = p[order] <= (np.arange(1, m + 1) / m) * q
    k = np.where(passed)[0].max() + 1 if passed.any() else 0
    out = np.zeros(m, bool); out[order[:k]] = True
    return out

pv = [0.001, 0.008, 0.039, 0.041, 0.042, 0.06, 0.074, 0.205, 0.212, 0.216]
bonf = np.array(pv) < 0.05 / len(pv)
bh = bh_reject(pv, 0.05)
print("개별 5%:", int((np.array(pv) < 0.05).sum()), "Bonferroni:", int(bonf.sum()), "BH:", int(bh.sum()))
assert (np.array(pv) < 0.05).sum() == 5 and bonf.sum() == 1 and bh.sum() == 2

import numpy as np

rng = np.random.default_rng(7)
false_pos = []
for _ in range(2000):
    p = rng.uniform(size=20)                      # 20개 모두 귀무가설이 참
    false_pos.append((p < 0.05).any())
print("한 번이라도 '유의'가 나올 비율", round(float(np.mean(false_pos)), 3))
assert abs(np.mean(false_pos) - 0.6415) < 0.04

변수 선택, 구간 분할, 모형 비교, 하이퍼파라미터 탐색 모두 암묵적 다중검정이다. 시도한 횟수를 기록하고, 최종 판단은 봉인된 테스트에서 한다(단계 12).

4-5. 통계적 유의성 vs 실무적 유의성

AUROC 차이 0.002 가 표본 100만 건에서는 '유의'할 수 있지만 승인율·손실에 미치는 영향은 무시할 수준일 수 있다. 반대로 소표본에서 0.03 차이가 '유의하지 않음'일 수 있다. 어느 쪽이든 효과 크기와 신뢰구간, 사업 영향(예: 같은 승인율에서 부도율 변화) 으로 판단한다.

5. 가정

  • 검정에 쓰는 표본이 독립(또는 군집 구조를 반영)이다.
  • 검정할 가설을 데이터를 보기 전에 정했다(사후에 고르면 p-value 가 무의미).
  • DeLong: 표본이 충분하고 두 모형이 같은 표본으로 평가되었다.

6. 한계와 오용

자주 하는 오용

  • p-value 를 "가설이 맞을 확률"로 읽는다.
  • p=0.049 와 0.051 에 질적 차이를 둔다. 유의수준은 관행이다.
  • 여러 모형을 시도해 가장 좋은 것만 검정하고 보정하지 않는다(p-hacking).
  • 독립 표본용 t-검정을 같은 고객으로 평가한 두 AUROC에 적용한다.
  • 고객당 여러 행인데 행을 독립으로 취급한다.
  • 유의하지 않다고 "동등하다"고 결론짓는다(동등성 검정은 별도).

정답 보기

Q3. 같은 테스트 고객으로 평가한 두 모형의 AUROC 를 독립 t-검정으로 비교하면?

4-1. 선택 편향 재현

과거에 위험 점수가 낮고 심사역 인상이 좋은 60%만 승인했다고 하자. 승인자만으로 학습·평가하면 위험 범위가 잘려 변별력이 낮아 보이고, 부도율과 예측 PD 가 전체 신청자보다 크게 낮다.

import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from creditlab.data import make_synthetic_credit_data

df = make_synthetic_credit_data(n=20000, seed=71).dropna().reset_index(drop=True)
feats = ["age", "income_10k", "loan_amount_10k", "employment_years", "card_utilization", "num_delinq_12m", "inquiries_6m"]
rule = df["num_delinq_12m"] * 1.5 + df["card_utilization"] * 3 + df["inquiries_6m"] * 0.3   # 과거 심사 규칙(가정)
rng = np.random.default_rng(0)
officer = df["default"] * 1.0 + rng.normal(0, 1, len(df))     # 심사역의 비정형 인상: 결과와 상관, 하지만 데이터 변수에는 없음
z = lambda s: (s - s.mean()) / s.std()
policy = z(rule) + 1.5 * z(officer)
accepted = policy <= policy.quantile(0.60)

train_idx = np.arange(len(df)) < 14000
dev, hold = df[train_idx], df[~train_idx]
acc_dev = dev[accepted[train_idx]]
acc_hold = hold[accepted[~train_idx]]

make = lambda: make_pipeline(StandardScaler(), LogisticRegression(max_iter=2000))
m_acc = make().fit(acc_dev[feats], acc_dev["default"])        # 승인자만으로 학습
m_all = make().fit(dev[feats], dev["default"])                # (참고) 전체로 학습: 현실에선 거절자 결과를 모름

print("부도율 승인자", round(acc_dev["default"].mean(), 3), "전체", round(dev["default"].mean(), 3))
auc_on_acc = roc_auc_score(acc_hold["default"], m_acc.predict_proba(acc_hold[feats])[:, 1])
auc_on_all = roc_auc_score(hold["default"], m_acc.predict_proba(hold[feats])[:, 1])
print("승인자 학습 모형 AUROC  승인자 구간:", round(auc_on_acc, 3), " 전체 신청자:", round(auc_on_all, 3))
pd_pred = m_acc.predict_proba(hold[feats])[:, 1].mean()
print("전체 신청자 예측 평균 PD", round(pd_pred, 3), "실제", round(hold["default"].mean(), 3))
assert acc_dev["default"].mean() < dev["default"].mean()       # 승인자의 부도율이 더 낮다
assert auc_on_acc < auc_on_all                                 # 범위 제한(range restriction)으로 승인자 안에서는 변별력이 낮아 보인다
assert pd_pred < hold["default"].mean()                        # 승인자만 본 모형은 전체 모집단의 위험을 과소추정

왜 이렇게 크게 틀어지는가: 과거 승인이 데이터에 있는 변수(연체·사용률)만으로 결정되었다면, 올바르게 설정된 모형은 승인자만으로 학습해도 전체를 꽤 잘 예측한다(관측 변수에 의한 선택). 편향이 커지는 것은 승인이 데이터에 없는 정보(심사역의 인상, 서류, 영업 판단)에 의존해 결과와 상관될 때다. 위 코드는 그 상황을 officer 로 주입했다. 실제 데이터에서는 officer 가 얼마나 큰지 알 수 없다는 것이 문제다.

거절 추론 기법은 가정에 의존한다. 어떤 가정도 거절자의 진짜 결과를 대체하지 못한다. 가장 신뢰할 만한 방법은 소액·통제된 무작위 승인(실험) 이나 외부 신용정보로 거절자의 이후 성과를 관찰하는 것이다. 이 프로그램은 거절 추론 기법을 결과를 개선하는 마법이 아니라 편향의 크기를 가늠하는 도구로 소개한다.

4-2. 기대신용손실(ECL)

\[\mathrm{ECL}=\mathrm{PD}\times\mathrm{LGD}\times\mathrm{EAD}\]

  • PD: 부도확률(12개월 또는 전체 만기), LGD: 부도 시 손실률, EAD: 부도 시 노출액.
  • IFRS 9 은 신용위험이 유의하게 증가했는지에 따라 12개월 ECL(1단계) 또는 전체 만기 ECL(2·3단계)을 쓴다. 보정된 PD 가 핵심이다.
pd_, lgd, ead = 0.05, 0.45, 1000.0
ecl = pd_ * lgd * ead
print(ecl)
assert abs(ecl - 22.5) < 1e-12

# 포트폴리오: 등급별 합산
grades = [  # (고객 수, PD, LGD, EAD)
    (1000, 0.01, 0.45, 1000.0),
    (500, 0.05, 0.45, 1000.0),
    (100, 0.20, 0.45, 1000.0),
]
total = sum(n * p * l * e for n, p, l, e in grades)
print(total)
assert abs(total - (1000 * 0.01 * 450 + 500 * 0.05 * 450 + 100 * 0.20 * 450)) < 1e-9   # 4500+11250+9000
assert abs(total - 24750.0) < 1e-9

보정이 틀려 PD 가 절반으로 과소추정되면 충당금도 절반으로 과소계상된다. 단계 12 의 보정이 회계 숫자로 이어진다.

4-3. 설명: 불이익 사유 후보

로지스틱 모형에서 변수 \(j\) 의 기여도(평균 고객 대비)는 \(c_j=\beta_j(x_j-\bar x_j)\) 이며, \(\text{logit}(x)-\text{logit}(\bar x)=\sum_j c_j\) 이다. 기여도가 큰 양수(위험 증가) 변수가 거절 사유 후보다. 사용자에게 보이는 문구, 사유 개수, 변수-문구 매핑은 법무·소비자 보호 부서의 기준을 따른다.

import numpy as np

lr = m_all.named_steps["logisticregression"]
sc = m_all.named_steps["standardscaler"]
Xh = hold[feats].to_numpy()
i = 0
z = sc.transform(Xh[[i]])[0]                     # 표준화 점수(= (x-평균)/표준편차)
contrib = lr.coef_[0] * z                       # 평균 고객 대비 로그오즈 기여도
logit_i = lr.intercept_[0] + (lr.coef_[0] * z).sum()
logit_mean = lr.intercept_[0]                   # 표준화 평균 고객의 로그오즈
assert abs((logit_i - logit_mean) - contrib.sum()) < 1e-12        # 기여도의 합 = 평균 고객과의 로그오즈 차이
top = [feats[j] for j in np.argsort(-contrib)[:3]]
print("위험을 가장 많이 올린 변수 후보:", top, np.round(np.sort(contrib)[::-1][:3], 3))

상관된 변수가 있으면 기여도가 나뉘어 사유가 불안정해진다. 사유 산출 방법은 고정하고 검증한다.

4-4. 공정성: 계산은 쉽고 해석은 어렵다

가장 단순한 지표는 집단별 승인율의 비율이다.

\[\text{승인율 비율}=\frac{\text{승인율}_{\text{집단 A}}}{\text{승인율}_{\text{집단 B}}}\]

(미국 일부 지침의 "4/5 규칙"은 0.8 을 경고 신호로 쓰지만 법적 판단 기준이 아니고 국가·분야마다 다르다.) 지표는 여러 가지(승인율, 오류율, 보정)이며 동시에 모두 만족시킬 수 없는 경우가 있다(Kleinberg et al., 2016; Chouldechova, 2017).

import numpy as np

def approval_ratio(approved, group):
    approved, group = np.asarray(approved), np.asarray(group)
    rates = {g: approved[group == g].mean() for g in np.unique(group)}
    lo, hi = min(rates.values()), max(rates.values())
    return rates, lo / hi

rates, ratio = approval_ratio([1] * 6 + [0] * 4 + [1] * 8 + [0] * 2, ["A"] * 10 + ["B"] * 10)
print(rates, round(ratio, 3))
assert abs(ratio - 0.75) < 1e-12

# 우리 합성 데이터의 '지역'별 승인율 (지역이 보호 속성의 프록시일 수 있음에 유의)
cut = np.quantile(m_all.predict_proba(dev[feats])[:, 1], 0.7)
approved = (m_all.predict_proba(hold[feats])[:, 1] < cut).astype(int)
rates_r, ratio_r = approval_ratio(approved, hold["region"].to_numpy())
print({k: round(float(v), 3) for k, v in rates_r.items()}, round(float(ratio_r), 3))
assert 0 < ratio_r <= 1

4-1. 축소판 전체 흐름 (재현 가능)

아래는 교육용 최소 구현이다. 실제 프로젝트에서는 각 단계를 별도 모듈·테스트로 분리한다. 모든 적합(비닝 경계, 대체값, 모형)은 개발 구간에서만 수행한다.

import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score, brier_score_loss
from creditlab.data import make_synthetic_credit_data
from creditlab import set_seed

set_seed(42)
df = make_synthetic_credit_data(n=15000, seed=81).sort_values("application_date").reset_index(drop=True)
TARGET = "default"
num_cols = ["age", "income_10k", "loan_amount_10k", "employment_years", "card_utilization", "num_delinq_12m", "inquiries_6m"]

# 1) 시간 기준 분할: 개발 60% / 검증 20% / OOT 20%
n = len(df)
dev, val, oot = df.iloc[: int(n * .6)], df.iloc[int(n * .6): int(n * .8)], df.iloc[int(n * .8):]
assert dev["application_date"].max() <= val["application_date"].min() <= oot["application_date"].min()

# 2) 비닝 경계와 WOE 는 개발 구간에서만 학습 (WOE = ln(%bad/%good), 높을수록 위험)
def fit_bins(s, y, q=5):
    edges = np.unique(np.quantile(s.dropna(), np.linspace(0, 1, q + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    b = pd.cut(s, edges)
    g = pd.DataFrame({"bin": b.astype(object).where(b.notna(), "MISSING"), "y": y})
    t = g.groupby("bin", observed=True)["y"].agg(bad="sum", n="count")
    t["good"] = t["n"] - t["bad"]
    adj = 0.5                                                  # 0 빈도 보호(스무딩)
    t["woe"] = np.log(((t["bad"] + adj) / (t["bad"].sum() + adj * len(t))) / ((t["good"] + adj) / (t["good"].sum() + adj * len(t))))
    return edges, t["woe"].to_dict()

def apply_bins(s, edges, woe):
    b = pd.cut(s, edges)
    lab = b.astype(object).where(b.notna(), "MISSING")
    return lab.map(woe).fillna(0.0).astype(float)       # 개발에 없던 구간은 중립(0)

bins = {c: fit_bins(dev[c], dev[TARGET]) for c in num_cols}
W = lambda d: pd.DataFrame({c: apply_bins(d[c], *bins[c]) for c in num_cols})
Wd, Wv, Wo = W(dev), W(val), W(oot)

# IV 로 변수 정렬 (개발 구간)
def iv(c):
    edges, woe = bins[c]
    b = pd.cut(dev[c], edges); lab = b.astype(object).where(b.notna(), "MISSING")
    tab = pd.crosstab(lab, dev[TARGET]); pb, pg = tab[1] / tab[1].sum(), tab[0] / tab[0].sum()
    return float(((pb - pg) * np.log((pb + 1e-9) / (pg + 1e-9))).sum())
ivs = pd.Series({c: iv(c) for c in num_cols}).sort_values(ascending=False)
print(ivs.round(3).to_dict())

# 3) 로지스틱: WOE 입력, 계수 부호 검토 (WOE 정의상 +, 높을수록 위험)
lr = LogisticRegression(C=np.inf, max_iter=2000).fit(Wd, dev[TARGET])
coefs = dict(zip(num_cols, np.round(lr.coef_[0], 3)))
print("계수", coefs)
assert (lr.coef_[0] > -0.2).all()           # 거의 모두 양(+) 이어야 정상 (심한 음수는 다중공선성 의심)

# 4) 점수 변환: Score = Offset + Factor * ln(odds_good), 600점@50:1, PDO 20
PDO, BASE, ODDS = 20, 600, 50
factor = PDO / np.log(2)
offset = BASE - factor * np.log(ODDS)
assert abs(factor - 28.8539) < 1e-4 and abs(offset - 487.123) < 1e-3
logit_pd = lambda W_: lr.intercept_[0] + W_.to_numpy() @ lr.coef_[0]
score = lambda W_: offset + factor * (-logit_pd(W_))               # ln(odds_good) = -logit(PD)
s_val, s_oot = score(Wv), score(Wo)
assert abs(np.corrcoef(s_val, -logit_pd(Wv))[0, 1] - 1) < 1e-12     # 점수와 로그오즈는 정확히 선형

# 5) 평가: 검증 / OOT, PD 보정 확인
for name, Wx, d in [("검증", Wv, val), ("OOT", Wo, oot)]:
    p = 1 / (1 + np.exp(-logit_pd(Wx)))
    a = roc_auc_score(d[TARGET], p)
    print(name, "AUROC", round(a, 3), "Gini", round(2 * a - 1, 3), "Brier", round(brier_score_loss(d[TARGET], p), 4),
          "평균PD", round(p.mean(), 3), "실제", round(d[TARGET].mean(), 3))
auc_oot = roc_auc_score(oot[TARGET], 1 / (1 + np.exp(-logit_pd(Wo))))
assert auc_oot > 0.65
assert abs((1 / (1 + np.exp(-logit_pd(Wo)))).mean() - oot[TARGET].mean()) < 0.03

import pandas as pd

p_dev = 1 / (1 + np.exp(-logit_pd(Wd)))
cuts = np.quantile(p_dev, [0.2, 0.4, 0.6, 0.8])          # 개발 구간에서 5등급 경계 고정

    return pd.cut(p, [-np.inf, *cuts, np.inf], labels=list("ABCDE"))     # A 가 가장 안전
tab = []

    r = d.groupby(g.to_numpy(), observed=True)[TARGET].mean().reindex(list("ABCDE"))

tab = pd.concat(tab, axis=1)

4-3. PSI 와 챌린저

import numpy as np
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score

def psi(e, a, bins=10, eps=1e-4):
    edges = np.unique(np.quantile(e, np.linspace(0, 1, bins + 1))); edges[0], edges[-1] = -np.inf, np.inf
    pe = np.clip(np.histogram(e, edges)[0] / len(e), eps, None)
    pa = np.clip(np.histogram(a, edges)[0] / len(a), eps, None)
    return float(((pa - pe) * np.log(pa / pe)).sum())

s_dev = score(Wd)
print("점수 PSI 검증", round(psi(s_dev, s_val), 4), "OOT", round(psi(s_dev, s_oot), 4))
assert psi(s_dev, s_val) < 0.1

gb = HistGradientBoostingClassifier(max_depth=3, learning_rate=0.05, max_iter=150, min_samples_leaf=50, random_state=0)

  • 교육용 합성데이터의 AUROC 를 현실 성능처럼 말한다.
  • 점수 변환 수식의 방향(높을수록 안전)을 문서와 코드가 다르게 쓴다.
  • 계수 부호가 이상한데 이유를 확인하지 않는다.

9. 지식 확인

Q1. 비닝 경계를 전체 데이터로 만든 뒤 시간 분할했다. 무엇이 문제인가?

정답 보기

검증/OOT 구간의 분포가 개발 단계에 새어 들어간 누수다. 경계·WOE·대체값은 개발 구간에서만 학습한다.

Q2. 점수 600 에서 PDO 20 이면 점수 620 의 odds(good:bad)는?

정답 보기

PDO 는 odds 가 2배가 되는 점수 증가량이다. 600점이 50:1 이면 620점은 100:1.

Q3. OOT AUROC 가 개발 구간보다 크게 낮다. 가능한 원인 세 가지는?

정답 보기

과적합, 모집단·분포 변화(PSI 확인), 거시환경 변화(관계 변화), 레이블 성숙도 부족, 누수 때문에 개발 성능이 낙관적이었을 가능성 등.

Q4. 챌린저가 OOT AUROC 를 0.004 높였다. 교체하는가?

정답 보기

DeLong 신뢰구간과 같은 승인율에서의 손실 변화, 설명·운영 비용을 본 뒤 결정한다. 차이가 구간 안이면 교체 근거가 약하다.

최종 과제: UCI 신용카드 데이터(가능하면) 또는 합성데이터로 위 10개 산출물을 모두 만들어 제출한다. 결과가 좋지 않아도 한계와 원인 분석을 정직하게 쓰면 높은 점수를 받을 수 있다.
