단계 1. 신용평가 문제 정의와 모집단 선정

모형 개발의 첫 단계는 알고리즘이 아니라 "무엇을, 누구에 대해, 언제부터 언제까지 예측하는가"를 문서로 고정하는 일이다.

연결 실습: 노트북 01_what_is_credit_model, 02_rows_columns_target · 템플릿 docs/target_definition_template.md

학습 목표

  • 관측단위·기준시점·관측창·성과관찰창·부도 정의를 구분해 말할 수 있다.
  • 개발모집단과 적용모집단이 다를 때 생기는 선택 편향을 설명한다.
  • 제외 기준을 정하고 제외 건수를 단계별로 추적한다.
  • 표본 수와 이벤트(부도) 수가 왜 따로 중요한지 설명한다.
  • 타깃 정의서를 작성하고, 데이터 분할 전에 모집단 정의를 고정해야 하는 이유를 말한다.

1. 왜 생겼는가

초기 대출 심사는 심사자의 경험에 의존했다. 같은 신청자도 사람마다 판단이 달랐고, 판단의 근거는 기록되지 않았다. 20세기 중반 이후 과거 대출의 결과(상환/연체)와 신청 시점 정보의 관계를 통계로 정리해 일관된 점수를 만들려는 시도가 상용화되었다.

그런데 통계모형은 "무엇을 맞힐지"가 정해져야만 만들 수 있다. 같은 연체 데이터라도 30일 연체를 부도로 보는지, 90일 연체를 부도로 보는지, 6개월을 보는지 12개월을 보는지에 따라 부도율도, 변수의 중요도도, 모형도 달라진다. 은행 규제(바젤)가 부도의 참조 정의와 PD 추정 관점(통상 1년 기간)을 정리한 이유가 여기에 있다.

2. 왜 필요한가

타깃 정의는 이후 모든 단계의 기준이다.

  • 정의가 흔들리면 개발 때와 운영 때 숫자가 맞지 않는다(예: 개발은 90일, 모니터링은 30일 기준).
  • 정의가 모호하면 검증자가 결과를 재현할 수 없다.
  • 모집단이 잘못되면 아무리 좋은 모형도 쓰일 곳과 다른 사람들에 대해 학습한 것이 된다.

3. 무엇을 하는가

타깃 정의서를 쓴다. 최소한 다음 7가지를 문장이 아니라 측정 가능한 규칙으로 적는다.

항목 질문 예 (가상 소액신용대출)
관측단위 행 1개는 무엇인가 대출 신청 1건 (고객 단위 중복 제거 후)
기준시점 설명변수는 어느 시점 정보인가 신청일 현재
관측창 변수를 만드는 과거 기간 신청일 이전 12개월
성과관찰창 부도를 관찰하는 기간 대출 실행 후 12개월
부도 정의 무엇이 1인가 성과관찰창 내 원리금 90일 이상 연체
모집단·제외 누구를 포함/제외하는가 실행된 신규 대출, 만 19세 이상, 중복·테스트 계좌 제외
출처 데이터 출처·라이선스 내부 DW (교육에서는 공개 데이터)

시간 관계는 그림으로 그려 보면 가장 분명하다.

과거  ───────────── 관측창(변수 산출) ───────────┤ 기준시점(신청일) ├─────── 성과관찰창(부도 관찰) ───────▶ 미래
      [ 신청 이전 12개월 정보 ]                       ▲                   [ 이후 12개월 동안 90일 이상 연체? ]
                                                 이 시점에 '알 수 있는' 정보만 변수로 사용

4. 어떻게 작동하는가

4-1. 부도 정의와 cure/재부도

부도 정의는 보통 연체 일수 기준과 상환 가능성 기준으로 구성된다. 바젤 규제의 참조 정의는 90일 초과 연체 또는 채무자가 채무를 이행하지 못할 가능성이 높다고 판단되는 경우(unlikely to pay)를 포함한다. 실제 국가·은행별 적용은 해당 시점의 감독규정과 내부 방법론을 확인해야 한다.

연체했다가 정상으로 돌아온(cure) 경우도 정의가 필요하다. 일정 기간(관찰 유예기간, probation) 정상이면 부도에서 벗어난 것으로 보고, 그 이후 다시 연체하면 재부도(re-default) 로 볼지 같은 규칙을 문서화한다. 이 규칙이 다르면 같은 포트폴리오의 부도율이 달라진다.

4-2. 개발모집단과 적용모집단: 선택 편향

대출 모형은 흔히 승인되어 대출이 실행된 사람의 성과만 관측된다.

구분 설명 문제
적용모집단(through-the-door) 모형을 실제로 쓸 신청자 전체 거절된 사람의 부도 여부는 모름
개발모집단 성과가 관측된 사람 과거 심사 정책이 걸러낸 사람들만 있음

과거 정책이 위험한 사람을 이미 많이 걸렀다면, 개발 데이터에는 그런 사람이 적다. 이 데이터로 만든 모형은 위험한 구간에서 정보가 부족하다. 이를 선택 편향(selection bias) 이라 한다. 거절 고객의 성과를 추정해 보완하려는 방법을 reject inference(augmentation, parceling, fuzzy augmentation 등)라 하지만, 관측되지 않은 결과를 가정으로 채우는 방법이라 효과는 가정에 크게 의존하고 학술적으로도 논쟁이 있다(Crook & Banasik, 2004). 따라서 한계를 문서화하고 민감도를 확인하는 것이 현실적인 접근이다.

4-3. 그 밖의 편향과 시점 문제

  • 생존 편향: 오래 유지된 계좌만 남은 데이터로 학습하면 이미 부도난 계좌가 사라진 표본이 된다.
  • 시점 불일치: 설명변수 일부가 기준시점 이후에 갱신된 값이면 미래 정보가 섞인다(단계 2의 누수).
  • 중복 고객/계좌: 한 고객이 여러 행이면 같은 사람이 학습·검증에 동시에 들어갈 수 있다(단계 8의 그룹 분할).
  • 표본추출: 부도가 드물면 부도 표본을 많이 뽑는 층화 추출을 쓸 수 있으나, 이때는 표본가중치로 실제 부도율을 복원해야 확률이 맞는다.

4-4. 표본 수와 이벤트 수

로지스틱 회귀의 추정 정밀도는 전체 건수가 아니라 적은 쪽 클래스의 건수에 크게 좌우된다. 10만 건 중 부도가 50건이면 정보량은 사실상 50건 수준이다. "변수 하나당 이벤트 10건" 같은 경험칙이 쓰이지만, 이는 통계적 법칙이 아니며 필요한 표본 크기는 목적·모형 복잡도에 따라 달라진다(van Smeden et al., 2019). 이 프로그램은 sample_sufficiency() 로 경고만 한다.

4-5. 제외 건수 추적

모집단을 줄여 갈 때는 어떤 규칙이 몇 건을 제외했는지를 순서대로 기록한다. 아래 표는 가상의 예다.

단계 규칙 제외 남은 건수
0 기간 내 신청 전체 - 10,000
1 중복 신청 제거 200 9,800
2 대상 아님(법인·미성년 등) 100 9,700
3 거절/미실행(성과 미관측) 2,200 7,500

최종 개발 대상 7,500건 중 부도가 300건이면 부도율은 300 ÷ 7,500 = 4.0% 다. 미실행 2,200건은 성과를 모르는 사람이므로 선택 편향의 원인이 된다는 점도 같이 기록한다.

import pandas as pd

def apply_exclusions(df, rules):
    """rules: [(규칙 이름, 제외 조건을 돌려주는 함수)]. 순서대로 적용하며 제외 건수를 기록한다."""
    log, current = [{"step": "시작", "excluded": 0, "remaining": len(df)}], df
    for name, cond in rules:
        mask = cond(current)
        log.append({"step": name, "excluded": int(mask.sum()), "remaining": int((~mask).sum())})
        current = current[~mask]
    return current, pd.DataFrame(log)

apps = pd.DataFrame({
    "id": [1, 2, 2, 3, 4, 5],
    "age": [30, 17, 17, 45, 52, 38],
    "approved": [1, 1, 1, 0, 1, 1],
})
kept, funnel = apply_exclusions(apps, [
    ("중복 ID", lambda d: d["id"].duplicated()),
    ("만 19세 미만", lambda d: d["age"] < 19),
    ("미승인(성과 미관측)", lambda d: d["approved"] == 0),
])
print(funnel)
assert funnel["remaining"].tolist() == [6, 5, 4, 3]
assert kept["id"].tolist() == [1, 4, 5]

5. 가정

  • 부도 정의와 성과관찰창은 개발·검증·운영에서 같다(또는 차이가 문서화되어 있다).
  • 개발모집단은 적용모집단을 충분히 대표한다. 대표하지 못하면 그 차이를 알고 있어야 한다.
  • 설명변수는 기준시점에 실제로 이용 가능하다(데이터 지연·소급 수정 포함).
  • 관측단위의 독립성: 같은 고객의 여러 행은 독립이 아니다.

6. 한계와 오용

자주 하는 오용

  • 데이터를 먼저 분할하고 나중에 제외 기준을 바꾸면, 검증 데이터의 정의가 학습 데이터와 달라진다. 모집단 정의를 먼저 고정한 뒤 분할한다.
  • 성과관찰창이 끝나지 않은 최근 신청 건을 "정상"으로 처리하면 부도율이 과소추정된다(아직 부도 날 시간이 없었을 뿐이다).
  • 부도율이 낮다고 해서 표본이 충분하다는 뜻이 아니다. 이벤트 수로 판단한다.
  • reject inference 결과를 "거절 고객의 진짜 성과"처럼 말하지 않는다. 그것은 가정의 산물이다.
  • 공개 데이터의 타깃 정의(예: UCI 의 1개월 후 결제 불이행)는 은행 IRB 의 12개월 부도 정의와 다르다.

7. 대안 및 비교

질문 선택지 비교
성과관찰창 6개월 / 12개월 / 24개월 짧으면 빨리 개발 가능하나 부도 건수 적고 정의가 불안정, 길면 최신성 저하
부도 기준 30일 / 60일 / 90일 낮을수록 건수 많으나 일시 연체가 섞임
단위 신청 단위 / 고객 단위 신청 단위는 신규 심사에, 고객 단위는 행동평점에 적합
선택 편향 무시 / reject inference / 일부 무작위 승인 실험 비용·윤리·규제 문제가 따름

8. 실무 적용

  • 타깃 정의서와 모집단 규칙을 코드와 같은 저장소에 버전 관리한다.
  • 규제 로지스틱 CSS와 AI 모델은 같은 타깃·같은 모집단·같은 분할을 써야 비교가 공정하다.
  • 제외 건수 표(깔때기)를 개발 보고서에 넣는다. 검증자가 가장 먼저 보는 표 중 하나다.
  • 모형의 PD 는 "정의된 성과관찰창에서 정의된 부도가 날 확률"이다. 다른 정의로 해석하지 않는다.
  • 이 프로그램의 데이터 레지스트리(config/datasets.yaml)는 각 데이터셋의 타깃 정의와 한계를 기록한다.

9. 지식 확인

Q1. 설명변수에 "신청 후 3개월째 연체 여부"가 들어 있다. 무엇이 문제인가?

정답 보기

기준시점(신청일) 이후 정보라서 미래 정보(누수) 이다. 학습 성능은 올라가지만 신청 시점에는 존재하지 않는 값이라 운영에서 쓸 수 없다.

Q2. 최근 3개월 신청 건의 성과관찰창이 아직 끝나지 않았다. 이 건들을 정상(0)으로 두고 부도율을 계산하면?

정답 보기

부도율이 과소추정된다. 아직 부도가 날 시간이 충분히 지나지 않은 건을 정상으로 센 것이다. 성과관찰창이 완료된 건만 개발 대상에 포함하거나, 불완전 관찰을 별도 처리한다.

Q3. 거절 고객은 성과를 모른다. 이 때문에 생기는 문제와 대응 방법 두 가지를 말하라.

정답 보기

개발 데이터가 과거 정책이 통과시킨 사람들로 치우쳐 선택 편향이 생긴다. 대응: (1) 한계를 문서화하고 모집단 차이를 점검, (2) reject inference 를 가정과 민감도 분석과 함께 적용하거나, 정책상 가능하다면 소규모 실험적 승인으로 정보를 얻는다.

Q4. 개발대상 10,000건 중 부도 40건이다. 변수 30개를 후보로 로지스틱 모형을 만들려 한다. 가장 먼저 걱정할 것은?

정답 보기

이벤트 수 40건으로는 추정이 불안정하고 과적합 위험이 크다. 변수 수를 줄이거나, 강한 규제(L1/L2)를 쓰거나, 더 긴 관찰기간·pooling 등 데이터 확보를 검토한다(단계 6, 15).
