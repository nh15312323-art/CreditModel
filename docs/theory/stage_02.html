단계 2. 데이터 품질과 탐색적 분석

모형은 데이터가 말하는 만큼만 안다. 결측·중복·이상치·타깃 누수를 먼저 찾고, 분포와 부도율을 눈으로 확인한 뒤에야 변수를 만진다.

연결 실습: 노트북 03_missing_and_quality · 코드 creditlab.data.validation, creditlab.reporting.quality_report

학습 목표

  • 데이터 사전을 만들고 단위·값 범위·자료형을 점검한다.
  • 결측의 세 가지 메커니즘(MCAR/MAR/MNAR)을 직관적으로 구분한다.
  • 이상치를 입력 오류와 실제 극단값으로 나누어 다룬다.
  • 타깃 누수 유형을 열거하고 의심 변수를 찾는 질문을 만든다.
  • 단변량 분석과 타깃별 비교를 수행하고, 하위집단의 데이터 충분성을 확인한다.

1. 왜 생겼는가

초기 모형 실패의 상당수는 알고리즘이 아니라 데이터 문제에서 나왔다. 예컨대 연체 후 회수 단계에서 생기는 필드를 변수로 쓰거나, 소득이 비어 있는 신청자가 사라진 표본으로 학습한 모형은 개발 때는 훌륭했으나 운영에서 무너졌다. 그래서 모형 개발 표준 절차에 탐색적 분석(EDA)과 데이터 품질 점검이 독립 단계로 자리 잡았다.

2. 왜 필요한가

  • 결측·오류는 통계량을 왜곡한다(평균, 상관, 부도율).
  • 누수는 성능을 부풀려 잘못된 확신을 준다.
  • 하위집단별 표본 부족은 일부 고객에게만 틀리는 모형을 만든다.
  • 검증자와 감독당국은 데이터 품질 점검 결과를 요구한다.

4. 어떻게 작동하는가

4-1. 데이터 사전

열마다 이름·자료형·단위·허용 범위·결측 의미·생성 시점·설명을 적는다. "소득"이 만원 단위인지 원 단위인지, 세전인지 세후인지 모르는 채로 분석하면 결과를 해석할 수 없다. 설명서와 실제 값을 비교해 불일치도 기록한다.

4-2. 결측: 세 가지 직관 (Rubin, 1976)

유형 의미 예 삭제의 영향
MCAR 비는 것이 완전 무작위 전산 장애로 임의 행의 일부 값 소실 편향은 적고 정보만 줄어듦
MAR 비는 확률이 관측된 다른 변수와 관련 근속연수가 짧은 사람이 소득을 안 적음 특정 집단이 사라져 편향 가능
MNAR 비는 확률이 비어 있는 값 자체와 관련 소득이 낮은 사람이 소득을 숨김 데이터만으로 확인 불가, 위험

데이터만으로 MCAR/MAR/MNAR 를 확정할 수 없다. 그룹별 결측률 비교는 "무작위가 아니다"를 시사할 수 있을 뿐이다. 처리 원칙은 다음과 같다.

  1. 먼저 왜 비었는지(시스템·입력 절차·업무)를 확인한다.
  2. 결측을 별도 범주/지표로 둘지, 대체할지, 제외할지 정하고 이유를 기록한다.
  3. 대체값(평균·중앙값 등)은 학습 데이터에서만 계산하고 검증·테스트에는 적용만 한다(누수 방지, 단계 8).
  4. 운영에서도 같은 이유로 비는지 모니터링한다.

4-3. 이상치: 오류인가, 실제인가

나이 150 세는 입력 오류일 가능성이 크지만, 소득 10억 원은 실제 극단값일 수 있다. 통계 규칙은 의심 후보를 찾을 뿐이다. 대표적인 IQR 규칙은 다음과 같다.

\[\text{하한}=Q_1-1.5\,\mathrm{IQR},\qquad \text{상한}=Q_3+1.5\,\mathrm{IQR},\qquad \mathrm{IQR}=Q_3-Q_1\]

import numpy as np

x = np.array([20, 22, 25, 27, 30, 31, 35, 38, 40, 41, 300], dtype=float)
q1, q3 = np.percentile(x, [25, 75])          # numpy 기본: 선형 보간
iqr = q3 - q1
low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr
print(q1, q3, iqr, low, high, x[(x < low) | (x > high)])
assert (q1, q3, iqr) == (26.0, 39.0, 13.0)
assert (low, high) == (6.5, 58.5)
assert x[(x < low) | (x > high)].tolist() == [300.0]

처리 방식(삭제, 결측 처리, 윈저라이징(상·하한으로 값을 자름), 로그 변환, 비닝)은 업무 판단이다. 비닝(단계 5)은 극단값의 영향을 자연스럽게 줄여 주는 장점이 있다.

4-4. 타깃 누수 점검표

누수(leakage) 는 모형이 운영 시점에는 알 수 없는 정보로 학습하는 것이다(Kaufman et al., 2012).

유형 예 질문
미래 정보 신청 후 3개월 연체 횟수 기준시점 이후에 생기는 값인가?
결과 이후 상태 회수 상태, 채권 매각 여부, 법적 조치 플래그 부도의 결과로 생기는 값인가?
승인 이후 변수 최종 승인 금리·한도 심사 결과가 반영된 값인가? (정책이 이미 위험을 반영)
타깃 파생 타깃을 가공해 만든 열 계산식에 타깃이 들어가는가?
식별자·순서 ID/일련번호가 시간 순서를 담음 키 값이 결과와 관련되는가?
전처리 누수 전체 데이터 평균으로 결측 대체, 전체로 변수 선택 검증·테스트 정보가 학습에 쓰였는가? (단계 8)

경험적 신호: 단일 변수로 비정상적으로 높은 IV·AUROC 가 나오면 누수를 먼저 의심한다. 규칙 기반 경고는 도움이 되지만 최종 판정은 사람이 한다.

import re

def leak_candidates(columns, patterns=("after", "post", "collect", "recover", "writeoff", "status", "result")):
    """열 이름만으로 만든 '의심 후보' 목록. 이름이 안전해 보여도 누수일 수 있으므로 점검표를 별도로 사용한다."""
    return [c for c in columns if any(re.search(p, c, re.I) for p in patterns)]

cols = ["age", "income", "collection_status", "months_after_open", "utilization"]
print(leak_candidates(cols))
assert leak_candidates(cols) == ["collection_status", "months_after_open"]

4-5. 단변량 분석과 타깃별 비교

  • 수치형: 평균·중앙값·분위수·왜도·결측률. 평균과 중앙값이 크게 다르면 치우친 분포다.
  • 범주형: 빈도, 희소 범주(건수가 매우 적은 범주), 범주별 부도율.
  • 타깃별 비교: 부도/정상 집단의 분포 차이, 변수 구간별 부도율.
  • 항상 건수와 이벤트 수를 함께 본다. 건수가 작은 구간의 부도율은 흔들린다(단계 1, 3의 신뢰구간).

4-6. 대표성과 하위집단

전체 표본이 충분해도 지역·연령대·상품별 부도 건수는 부족할 수 있다. 하위집단별 건수와 이벤트 수를 표로 만들고, 부족한 집단은 모형이 불안정할 수 있음을 기록한다. 개발 표본이 운영 모집단을 대표하는지(분포 비교)도 확인한다.

5. 가정

  • 데이터 사전의 의미·단위가 실제로 맞다는 가정(반드시 확인해야 함).
  • 오류 판단은 업무 규칙(허용 범위)에 근거한다. 규칙 자체가 틀릴 수 있다.
  • 결측 대체는 대체 방법이 타당할 때만 의미가 있다. 대체는 데이터를 만드는 행위다.

6. 한계와 오용

자주 하는 오용

  • 결측 행을 말없이 삭제한다 → 특정 고객군이 표본에서 사라진다.
  • 평균 대체를 전체 데이터로 계산한다 → 누수.
  • 이상치를 통계 규칙만으로 삭제한다 → 실제로 중요한 고위험·고소득 고객을 지운다.
  • "결측 자체가 정보"라는 이유로 결측 지표를 쓰되, 운영에서 결측 원인이 바뀌어도 방치한다.
  • 자동 EDA 보고서를 읽지 않고 첨부만 한다 → 보고서는 질문을 돕는 도구일 뿐이다.

7. 대안 및 비교

상황 선택지 장단점
결측 삭제 / 단순 대체 / 결측 범주 / 모형 기반 대체 삭제는 편향, 단순 대체는 분산 축소, 결측 범주는 해석이 쉬우나 운영 변화에 민감
이상치 유지 / 윈저라이징 / 변환 / 비닝 비닝은 스코어카드에 자연스럽고, 트리 모형은 극단값에 상대적으로 둔감
범주 희소 범주 병합 / 기타 병합 기준을 학습 데이터에서 정한다

8. 실무 적용

  • 규제 로지스틱 CSS: 결측·이상치 처리 규칙이 점수카드의 비닝 규칙(결측 bin, 극단값 구간)으로 명시된다. 규칙이 문서에 있어야 운영 시스템이 같은 결과를 낸다.
  • AI 모형: 트리 부스팅은 결측을 모형이 처리하기도 하지만(알고리즘별 방식이 다름), 그래도 누수와 정의 불일치는 모형이 해결해 주지 않는다.
  • 두 모형 모두 동일한 정제 규칙을 학습 데이터에서 정하고 검증·테스트·운영에 적용한다.
  • 품질 점검 결과는 build_quality_report 처럼 자동 생성 + 사람의 판단 기록으로 남긴다.

9. 지식 확인

Q1. 소득 결측률이 근속 1년 미만에서 28%, 1년 이상에서 3% 이다. 결측 행을 삭제하면?

정답 보기

근속이 짧은 고객이 표본에서 크게 줄어 모집단이 왜곡된다(MAR 성격). 삭제 전에 원인을 확인하고, 결측 범주/대체 중 무엇이 적절한지 검토한다.

Q2. 단일 변수의 AUROC 가 0.97 이다. 첫 반응은?

정답 보기

좋은 변수라고 기뻐하기 전에 누수를 의심한다. 생성 시점, 결과 이후 값 여부, 타깃과의 계산 관계를 확인한다.

Q3. 평균 대체를 전체 데이터로 하면 왜 문제인가?

정답 보기

검증·테스트 데이터의 정보가 평균에 섞여 학습 단계로 새어 들어간다. 운영에서는 미래 데이터의 평균을 알 수 없으므로, 학습 데이터에서만 통계를 계산하고 나머지에는 적용만 한다.

Q4. (코드 읽기) df[df["income"] != 0] 은 소득이 결측인 행을 포함하는가?

정답 보기

pandas 에서 NaN != 0 은 True 이므로 포함된다. 반대로 df["income"] == 0 은 결측을 제외한다. 결측이 있는 열로 필터링할 때는 건수를 확인한다.

실습 과제: 합성 데이터(오류 주입판)와 UCI 데이터에 점검 도구를 모두 적용하고, UCI 에서 "결측은 없지만 설명서와 다른 값"을 3개 이상 찾아 적어라.
